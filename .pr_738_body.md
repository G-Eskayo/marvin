Design for #737 (MR Review: owner feedback updates the same PR right away, and unapproved looks stay as archived variations). **Design only: no code, nothing wired.** Full write-up: `docs/design/737-review-variations.md`. Mock-up: `docs/design/737-review-variations-mockup.html`.

## Why
Today feedback waits for the hourly scan plus a 4 h grace (and that scan has failed since 2026-10-22, PR #724). The follow-up then builds from main, so it can land in a different PR. A denied round is rebuilt from main and force-pushed, so the old look survives only under `refs/rescue/`. clarity-captions #171 and #155 both hit this on 2026-10-27.

## Proposal
1. **Right away, same PR, no new loop.**
   - Submit decisions and Deny already run in the dashboard's main process. Right after GitHub accepts the write, they call the existing scan kick (`scanNow()` → `launchctl kickstart com.marvin.ticket-pipeline`).
   - That scan files the `owner_decisions` follow-up for that PR with no grace. The 4 h grace stays only as the hourly fallback, for answers written on github.com.
   - A follow-up that names `pr=N` is built on PR #N's own branch: commit on top, push without force, `pr-shots` re-pin, a reply with `<!-- marvin:decisions-addressed -->`, and a fresh Decisions section.
2. **Variations.**
   - A round is one `pr-shots` run: a SHA plus the images pinned to it.
   - When `pr-shots` re-pins, it first posts the outgoing round as a `<!-- marvin:variation v=N sha=… -->` comment. MR Review derives "Earlier versions" from those comments, so nothing is stored locally.
   - It also pushes `refs/marvin/variations/pr-<N>/v<k>`, so the pinned images keep loading after a squash merge, a deleted branch or a force-push.
   - "Go back to vN" is an owner answer like any other. The agent restores vN's look as a new commit, which becomes the next round.
