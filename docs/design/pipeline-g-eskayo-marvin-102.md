# Suggestions Dashboard Tab — Design & Implementation

## Overview

The Suggestions tab provides read-only visibility into the priority-ordered backlog of architecture and optimization suggestions generated by the `architecture-review` and `audit` skills. This pairs with the Files tab (#89) as a read-only capability in the MARVIN dashboard, allowing users to review what improvements are pending without needing to manually read `~/.claude/suggestions.md`.

## Design Decisions

### Reuse, Don't Duplicate

The parsing logic reuses `_split_entries()` and field regexes from `sort_suggestions.py` (the existing tool that maintains the suggestions file). This module is imported directly in `lib/suggestions_list.py:13`, not hand-rolled a second time. This is enforced by `test_no_duplication_of_parsing_logic`, which fails if a local regex definition is added.

### Worktree-Relative Imports

The Python IPC handler (`lib/suggestions_list.py`) uses a worktree-relative import path for `sort_suggestions`:
```python
sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "skills" / "architecture-review" / "scripts"))
from sort_suggestions import _split_entries, ...
```

This allows the script to run in both the real checkout and the isolated worktree without breaking when the home directory path diverges between `main` and feature branches.

### No Dashboard-Local Duplicate Parser

The dashboard does NOT include a `dashboard/lib/suggestions_list.py` copy. The single parser lives in `lib/suggestions_list.py` and is called via IPC from Node.js, matching the pattern used by `devices.js` and `health.js` (the only other sibling handlers).

### Error Handling: Always Valid JSON

The Python script guarantees valid JSON output on all code paths:
- Success: `[{ title, priority, status, impact, effort, body }, ...]`
- Any failure (import, file I/O, parse): `[]` to stdout, error message to stderr, exit code 1

The Node.js handler (`listSuggestions`) further guards against malformed data:
- JSON parse failure → `{ suggestions: [], error: "..." }`
- Non-array result → `{ suggestions: [], error: "Suggestions must be an array" }`

### Large Files & Buffer Overflow

The default Node.js `execFile` buffer is 1 MB. For large `suggestions.md` files, this would silently truncate the output. The fix is `{ maxBuffer: 10 * 1024 * 1024 }` (10 MB), enforced by `test_handles_large_payloads`, which fails if the buffer size is reduced.

### Encoding: Explicit UTF-8

The Python reader uses `file_path.read_text(encoding="utf-8")` with no `errors=` override. This means:
- Unicode content (emojis, accented characters, CJK) round-trips correctly.
- Binary garbage raises `UnicodeDecodeError` (asserted by `test_binary_garbage_raises_unicode_error`).
- The behavior is deterministic regardless of locale.

### Deferred Import Error Handling

The `sort_suggestions` import is deferred until `suggestions_list()` is called, not done at module scope. This allows the `__main__` handler's `except Exception` to catch import failures and output `[]` + error to stderr. Tested by `test_main_subprocess_missing_import`, which simulates the import failing and verifies the error path works.

| AC | Code |

| Parser reuses existing `_split_entries`, no duplication | `lib/suggestions_list.py:13` imports from `sort_suggestions`; test pinned by `test_no_duplication_of_parsing_logic` |

## Verify-Fails-When-Code-Changes

Each test is designed to catch a specific defect if the code is changed without updating the test:

| Test | Fails If |
|------|----------|
| `test_no_duplication_of_parsing_logic` | A local `*_RE =` definition is added (forces import, not duplication) |
| `test_applies_status_color_based_on_status_value` (Row) | `STATUS_COLORS` is swapped or deleted (targets the exact `<span>`) |
| `test_applies_correct_status_color` (Detail) | `STATUS_COLORS` is swapped or deleted (targets the exact `<span>`) |
| `test_handles_large_payloads` | `maxBuffer` is reduced below the test payload size |
| `test_rejects_non_array_json` | `Array.isArray` guard is removed |
| `test_binary_garbage_raises_unicode_error` | `encoding="utf-8"` is removed or `errors=` is added |
| `test_main_subprocess_missing_import` | Import is moved to module scope (defeats error handling) |
| `test_renders_markdown_formatting_in_body` | `Markdown` component is swapped for raw HTML interpolation |

## Known Limitations

- **Code-block headers:** The regex-based parser cannot distinguish `## Header` inside a markdown code block from actual entry headers. This is a known edge case; the workaround is to avoid `## ` in code snippets within entry bodies.
- **Resolved entries remain permanent:** Resolved entries are never automatically deleted from the file. Cleanup is manual via the `suggestions.md` editor.

## Future Enhancements (out of scope)
