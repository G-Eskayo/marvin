## North-star fit

**Reuses before adding anything new:** The tree already carries almost all of the fix from the last cycle's design (I read every touched file before writing this). `lib/health_checks.py:check_autonomous_share` already reads `rows` (not the capped `by_ticket`), already determines "today" from the latest row day relative to `now`, and already flips the threshold to green ≤50% / yellow >50% — exactly matching AC #4 and `lib/health_checks.py:442` (`check_catalog_fresh(path=None, now=None)`)'s injectable-path/`now` convention, which this function already follows. `dashboard/src/components/UsageView.jsx` already renders `<ShareLine>` overlaid on `<DailyBars>` inside a `relative` container, and `weeklySeries`/`topAutonomousSpenders` in `dashboard/src/lib/usage_view.js` already carry the `day`-alias and zero-autonomous-exclusion fixes with passing tests (`dashboard/test/usage_view.test.js` tests 16–20). None of that needs rework — re-deriving it would violate "research only the gaps."

What's left is the four concrete defects named in the review, all narrow:
1. `lib/health_checks.py:196` (+docstring ~154) and `CONTEXT.md:774` say "**interactive** work dominating" for the yellow case (autonomous >50%) — backwards. Fix is a one-word swap in three places, keeping the existing sentence structure (no new mechanism).
2. `dashboard/src/components/UsageView.jsx:16` `ShareLine`'s `<svg>` is `className="absolute w-full"` with no inset — needs `inset-0` added (the review names this as one of two sufficient fixes; `inset-0` is simpler than `top-3 left-3` since the container already has `position: relative` and `ShareLine`'s viewBox already matches `DailyBars`'s, so the padding-edge containing-block math lines up once an inset is given at all).
3. `dashboard/test/usage_view_render.test.jsx` hardcodes fixture dates against the *real* wall clock (`UsageView` computes `end` from `new Date()` internally, `UsageView.jsx:83`) instead of an injectable clock. The codebase already has an established pattern for this exact problem — `dashboard/src/components/MrReview.jsx:535` (`FetchBanner({ status, now = Date.now() })`) and `dashboard/src/components/HealthDashboard.jsx:80` (`RecentErrors({ errors, now = Date.now() })`) — both accept an optional `now = Date.now()` prop. Reusing that convention on `UsageView` (instead of inventing a `clock`/`end` prop) is the "simplest sufficient" fix and lets every existing render test pin its own date instead of drifting.
4. `lib/tests/test_health_checks.py`'s `test_check_autonomous_share_uses_local_machine_only` only asserts a percentage — it can't fail if the function reached another machine. The file already has the exact idiom for this (`monkeypatch.setattr(hc.subprocess, "run", ...)` at lines 221, 247, 921, used to prove other checks avoid SSH); reusing that idiom here (make it raise if called at all) is reuse, not new test infrastructure.

**Why simplest sufficient:** every remaining item is a one- or two-line correctness/wiring fix in code whose shape is already right. No new modules, no new data flow, no new component.

**Tokens:** small, net-few-line diff — three string edits, one CSS class, one optional prop + its default, a handful of test edits. Cheaper than either prior attempt.

**User capability:** unchanged from the ticket's own framing (observability only, nothing paused) — the fix specifically stops the health card and CONTEXT.md from telling Gil the *opposite* of what's happening when autonomous share is high, which is the one thing that would make him act on a wrong signal.

**Checked against the ticket's stated fit:** correct as stated; AC #4 ("yellow above 50%") already matches the shipped threshold and needs no change — only the *prose describing* that threshold is inverted.
