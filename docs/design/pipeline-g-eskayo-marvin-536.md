The newer, differently-named `'enrichment marker extraction from timeout'` describe block at 1388 *does* feed the current format correctly (1396-1408) but still only asserts `code`/`reengage`, never reading the thrown error's `message` to confirm the usual-duration/concurrent-count text actually made it in — so it also can't fail against a regression that silently drops the marker during extraction.

4. **`merge.test.js:1198-1219`, confirmed still broken.** `'ignores countConcurrent errors gracefully'` and `'timeout counts still work with no meta param (backward compat)'` both assert `expect(err.message).not.toContain('[concurrent-count:')` — a string the current code has never emitted (the format changed to `[usual: ...; concurrent: ...]` before either of these tests was written). 5. **New finding, not on the review's list, directly threatens AC3 — found by tracing the data flow, not assumed.** `execWithGroupTimeout` (`merge.js:42-65`) appends the `[usual: ...; concurrent: ...]` enrichment to `error.message` only; `error.stdout`/`error.stderr` stay as the raw captured process output. `rebaseAndRetest`'s failure path builds the refusal text via `testOutputOf(err)` (`merge.js:168-172`):
   ```js
   const rest = String(err?.stderr || err?.message || err)
   ```
   `rest` prefers `err.stderr` over `err.message`, falling back to `.message` **only when `.stderr` is empty**. A killed `pytest -q`/`npx vitest run` almost always has *some* stderr by the time it's killed (deprecation warnings, progress output, pytest's own `-q` writes some to stderr on interrupt) — so in the realistic case, `rest` picks the raw `.stderr`, which never contains the enrichment, and the marker is silently dropped before it ever reaches `result.reason`. `mergePrUnqueued`'s regex extraction at `merge.js:530` then finds nothing, and the refusal Gil reads has no usual-duration/concurrent-count info at all — AC3 fails exactly in the case it exists to help with (a real test run, not a trivial `sleep`). None of the existing tests exercise this because every timeout test in `merge.test.js` runs real `sleep`, which writes nothing to stderr. This is promoted into the required fixes below, with its own test, because it is a direct, demonstrable AC3 failure under realistic conditions, not a style nit.

One cheap, same-block fix bundled with finding 5 because it's free once that block is being rewritten anyway, not scope creep on its own: the 2-second fallback timer racing `meta.countConcurrent()` (`merge.js:55`) is never captured or cleared — if `countConcurrent()` settles before the 2s elapses, that inner timer keeps running regardless. Clearing it in a `finally` costs nothing extra since the block is already being touched.

One pre-existing test-quality item from the prior design doc that still wasn't applied, cheap, in a file already being edited for this ticket: `gate_durations.test.js:279-284`, `'returns at least 1 even if pgrep returns no lines'`, asserts `toBeGreaterThanOrEqual(0)` for `stdout: '\n'` — true regardless of the actual count, and the name doesn't match the assertion. Corrected to `toBe(0)` with an accurate name.
