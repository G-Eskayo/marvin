## North-star fit

**Reuses before adding anything new:** `bench/bench.py:run_hidden_check` (real pytest-based gate scoring), `bench/bench.py:_ollama_available` (Ollama/model preflight), and `bench/lib/score.py:score_correctness` (the `expect[]`-substring contract already used by `run_once_ollama`). All three already exist and are exercised elsewhere in `bench.py`. Most importantly: this worktree already has a fuller starting point than any of those three — two **rescue refs** left by this ticket's own prior redispatches today (`refs/rescue/.../20261123T120910Z` = `8a8fe733`, and the newer `refs/rescue/.../20261123T142147Z` = `823ee480`), each holding `bench/lib/opencode_runner.py`, `bench/lib/energy_apple.py`, `bench/lib/ticket_replay.py`, `bench/local_agent_spike.py`, 5 test files and a README section — ~2,600 lines already written and TDD'd. Recovering `823ee480` (the newer of the two) is far cheaper than a rewrite.

**Why it's the simplest sufficient approach, and why it keeps failing — root cause confirmed, not guessed:** I read `823ee480`'s actual code rather than trusting its own design doc's claim that the issue's must-fix #1 (any non-empty opencode output passes the gate, even on an error) was fixed. It was not — it was only *relabeled*:

- `bench/README.md` in that commit states the contract as: *"If no test files and no expected strings found, return `None` (not scored)."* But `local_agent_spike.py:score_gate_pass`'s actual last line, reached whenever `test_files` is falsy and no expected strings were derived, is `return bool(result_text)` — i.e. **any non-empty string still passes**, exactly the bug named in the issue, just no longer gated by a keyword scan. The code's own test suite enshrines this: `test_score_gate_passes_on_error_output_for_docs_only` and `test_score_gate_passes_on_any_output_docs_only` assert `gate is True` for result text reading `"Error: unable to process request"` and `"Exception: RuntimeError handled gracefully"`. A reviewer reading the README against the code (or the issue against the tests) will flag this every time — which is consistent with the pattern of repeated "review found must-fix issues" verdicts on this same ticket today (10:46 UTC and 13:13 UTC per the issue comments).
- This path is reached far more often than it looks, because the no-test-file branch's own `modified_files` filter in `score_gate_pass` is `f.endswith(".py")` — so a **docs-only** PR (the issue's own paradigm case, e.g. `.md` changes) never produces an `expected[]` list at all, and always falls through to the broken `bool(result_text)` fallback. The ticket's highest-priority example category is the one guaranteed to hit the unresolved bug.
- A second, smaller instance of the same defect class: `get_test_files` in `ticket_replay.py` was fixed to match real test-file names (`test_*.py` / `*_test.py`), but `score_gate_pass`'s own inline filter for "non-test files" still uses the naive `"test" in f.lower()` substring check — reintroducing the exact mis-filed-match bug in a second, duplicated piece of filter logic.
- Third: when `test_files` is present but `run_tests_from_paths` returns `None` (pytest infra error), the code's comment claims "return None (not scored)" but does not actually return — it falls through into the same `expect[]`/`bool(result_text)` heuristic path instead of staying unscored, contradicting the design doc's own stated test ("`run_hidden_check` returns `None` ... gate is `None` ... never silently falls through").

Fixing these specific, verified gaps in the recovered code — not rewriting it — is the simplest sufficient approach, and it directly targets why review keeps parking this ticket rather than guessing at a new cause.

**Resources:** this is a one-time measured spike ("no adoption yet"); the saving is recovering ~2,600 already-written, already-TDD'd lines from the rescue ref instead of re-deriving them, and fixing only the ~4 confirmed defects rather than re-reviewing everything from scratch. The real spend is the model pull and the five short live opencode/Ollama runs, which must happen **outside** the automated verification gate (two of the four historical parks before today were 1200s verify timeouts from running the live sweep inside that gate).

**Phone-OS / capability fit:** produces the one measurement #594/M3 needs — whether a "small tickets go local" lane exists before the $100 plan ends (Nov 27). Leaves Gil more capable: a result he can act on, not another parked review cycle repeating the same unresolved gate bug under new cover.

**Which machine:** the Mini — it already has Ollama and the free-disk headroom this ticket's own earlier research measured; local models stay instance-side per ADR 0071/0072 (confirmed against `CONTEXT.md:2002`), never in the engine repo.

## Tests to write FIRST

Spike has no "How we'll try to break it"/Attacks section; reusing the 35 already-TDD'd tests in the recovered `bench/tests/*` as the base, rewriting only where behavior must change, plus the standard misuse list:

1. **The real unresolved must-fix — no-test-file, no-expected-strings case.** `score_gate_pass(result, test_files=[], worktree_path=..., base_commit=..., merge_commit=..., repo_path=...)` where `get_expected_strings` returns `[]` (e.g. a docs-only PR touching only `.md` files) → gate is **`None`**, never `True`. Rewrite `test_score_gate_fallback_when_no_expected_strings` (currently asserts `True`) and delete/rewrite the three tests that assert `True` for `"Error: ..."` / `"Exception: ..."` text with no ticket context at all — those encode the exact bug.
2. **Docs-only ticket gets real scoring, not just `.py` files.** `modified_files` extraction must include non-`.py` text files touched by the merge (e.g. `.md`), not just `.py`, so `get_expected_strings` has something to scan for the issue's own named docs-fix category. Case: merge touches only `README.md` with a distinctive added line → that line appears in `expected[]` and scores against the agent's output/files.
3. **Mis-filed "test" match in `score_gate_pass`'s own filter** (new — found while reading, same class the issue named): a non-test file whose path contains the substring "test" (e.g. `latest_config.py`, `attestation.py`) must not be excluded from `modified_files`; replace the inline `"test" in f.lower()` check with the same basename-pattern helper `ticket_replay.py:get_test_files` already uses (extract a shared helper rather than duplicating the fixed logic a second time, to stop the two filters from diverging again).
4. **Docs-only correctness, positive and negative.** Case A: opencode writes "I fixed the error handling, this should resolve the issue" with no matching edit on disk → gate is `False`. Case B: opencode's edit actually contains the expected diff content → gate is `True`.
5. **`run_tests_from_paths` returns `None` (pytest infra error, test files present) → `score_gate_pass` returns `None` immediately**, never falls through to the diff/output heuristics. Rewrite the branch so `None` is an explicit early return, not an unenforced comment.
6. **Collection-safety regression** (keep, already exists — caught the historical 15-error pytest collection crash).
7. **`opencode_available()` missing CLI** → `(False, msg)`, never scored as if the agent ran (keep).
8. **Ollama down / model not pulled** → `main()` calls `bench.py:_ollama_available(model)` before `orchestrate_spike`; exits with a clear message, zero tickets run (keep — already implemented and tested in `823ee480`, verify it's still correct after the other changes).
9. **Energy cleanup ordering** (keep) — `measure_energy=True` with a `continue` path and with an exception inside the try: `ea.stop_sampling` still called exactly once per code path that started it; add the assertion the design doc flagged but didn't add — call count isn't silently masking a double-sample bug on the normal-completion path (outer `finally` calling `stop_sampling` again on an already-terminated handle).
10. **powermetrics dependency failing** (keep) — binary missing, `sudo -n` needs a password → `start_sampling` returns `None`; other metrics still score; no stuck subprocess (assert `terminate`/`kill` on a mock `Popen`).
11. **Bad/empty/huge/malformed opencode output** (keep) — non-zero exit, timeout, non-JSON stdout → recorded failure, never an uncaught exception, never silently scored as a pass.
12. **Repeats/concurrency** (keep) — same ticket run twice doesn't corrupt `RESULTS.md` (append-only); two spikes' worktrees get distinct paths and both clean up even if one fails.
