**Where it spends/saves tokens:** same bounded `gh`/`git` calls as before, halved for the GitHub-sourced pair by sharing one `gh pr list` fetch per repo between `check_mutation_trend` and `check_below_bar_merges` (via `check_all` passing a pre-fetched dict in, not two independent fetches). `check_repo_growth`'s file/folder/size walk switches from `Path.rglob` (which still *descends into* `.git` before filtering it out — wasteful on a large `.git`) to `os.walk` with `.git` pruned from `dirnames` before descent, and the per-top-level-folder first-touch check stays O(top-level dirs), not O(history) — this is the actual fix for the review's "huge repo" exposure, not just a token-cost nicety.

**"One Mac unreachable" (the ticket's own break-test case), checked against the code, not assumed:** `check_mutation_trend`/`check_below_bar_merges` talk only to GitHub (`gh pr list` — the same global data regardless of which Mac asks); `check_test_skips`/`check_repo_growth` read only local files (`~/.claude/logs/test-skips.jsonl`, `~/.agents`), both of which are already kept in sync across machines by ADR 0021/0022's existing bidirectional sync — **confirmed by reading `lib/quality_checks.py` end-to-end: it contains zero `ssh`/remote-host calls.** So "both Macs" visibility (acceptance criterion 1) and graceful behaviour when one Mac is unreachable both fall out of infrastructure that already exists; building a remote-reachability path into this module would be mechanism the task doesn't need (Watts check) — reuse over invention. I test this as an *integration* property (below), not by inventing a new SSH code path.

**User capability:** unchanged from the prior doc's correct framing — pure visibility/accountability plumbing for ADR 0063 gates 2–4, makes existing enforcement legible without automating any decision away from Gil. More capable, not more passive: he sees the actual trend and the actual reasons, nothing is decided for him.

## Tests to write first

All in `lib/tests/test_quality_checks.py` (rewritten, not just extended — several existing tests currently assert the buggy behavior and must be corrected, not kept) plus one integration test added to `lib/tests/test_health_checks.py`.

**Ticket's "How we'll try to break it", one test each:**
1. **No data yet** — zero merged PRs (gh returns `[]`), missing `test-skips.jsonl`, a freshly-created empty `repo_path` → every one of the four checks returns a result (never vanishes), green, `value=0`, no crash.
2. **One Mac unreachable** — integration test in `test_health_checks.py`: monkeypatch `hc.check_machine_reachability` to report the other Mac unreachable, call the real `hc.run_all()` (with the network-bound siblings below stubbed), assert all four `quality:*` ids are still present and unaffected by the unreachable-Mac entry. Plus a structural assertion that `lib/quality_checks.py`'s source contains no `"ssh"` call, locking in that these checks can't be blocked by the other Mac at all.
3. **A burst of skips in one day** — 50 entries within one hour in `test-skips.jsonl` → `value == 50`, severity yellow, no crash.
4. **A huge repo** — synthetic tree with thousands of files under a handful of top-level dirs plus a `.git` dir containing many files of its own; mock `subprocess.run` for the git calls. Assert: (a) the git-log mock is called exactly once per top-level dir, not per file or per commit; (b) `.git`'s files are excluded from the total count; (c) a broken symlink that raises `OSError` on `.stat()` is tolerated (doesn't zero out or crash the whole count, result still returned with the other files counted).
5. **A deleted metrics log** — two variants, both already-identified failure points: (a) `test-skips.jsonl` exists then is deleted between calls → next call reports green/no-log, not stale data; (b) the `health-monitor` metrics snapshot file is gone (`mr.latest` returns `None`) → `check_mutation_trend` reports green "first measurement," never misreported as regressed.

**Additional misuse the ticket's list didn't name, that the review findings make unavoidable:**
6. **`gh` missing from PATH** — mock `run` to raise `FileNotFoundError` (an `OSError` subclass) → caught, yellow "could not check", `value=None`, never silently dropped from `results` (this is the exact crash review item 1 found).
7. **`gh` unreachable another way** — non-zero exit, malformed JSON, timeout → same yellow-unknown outcome, one test each.
8. **Each dependency failing independently** — `git` missing/failing for repo-growth; `gh` failing for mutation-trend and below-bar *independently of each other* (one succeeds, one fails) via the shared-fetch path; `ticket_agents.board_repos()` raising; `project_profile.load_profile()` raising `ValueError` on a corrupt profile for one repo while a second repo in the same sweep succeeds.
9. **Repeats** — calling any check twice with identical mocked input returns identical results (pure reads, no hidden state).
10. **Wrong permissions** — unreadable log file (`PermissionError` on read) and unreadable `repo_path` (`PermissionError` on `iterdir`/`stat`) → caught, yellow/unknown, not a crash, not a false green.
11. **Stale state** — `mr.latest()` returns a bare float instead of the nested dict shape → doesn't crash, treated as no usable baseline.
12. **A person's mistakes** — `MARVIN_TEST_SKIP_LOG` pointed at a directory instead of a file (`IsADirectoryError`, an `OSError`) → caught; non-dict JSON line (`"[]"`, `"5""`) and an `at` field stored as an ISO string → both tolerated, valid lines around them still counted; a non-UTF-8 byte sequence in the log → tolerated via `read_text(errors="replace")`.
13. **The red/yellow rule itself, corrected** (review item 3's exact bugs): (a) a core-path change with zero test-file changes and score **≥80 or unmeasured** → still **red** (previously fell through to green — this was the review's named must-fix); (b) a non-core change with score 50% and tests that *did* change → **yellow** (below-bar is its own signal, independent of whether tests changed); (c) score ≥80% and no core-without-tests → green; (d) a non-home repo's `extra_core` path (from its project profile) is correctly classified as `"core"` via `amp.area(..., extra_core=...)` — previously always used the home repo's bare rules.
14. **Weekly new-top-level-folder count, corrected** (review item 4's exact bugs): a folder whose `git log --diff-filter=A -1` first-touch date is 8+ days ago is **not** counted even though it had an ordinary edit in the last 7 days (the exact false positive the rewrite was meant to remove); a folder first-touched 2 days ago **is** counted; a non-git or fully-unreadable `repo_path` **fails closed to yellow**, not a false green with `value=0`; missing/corrupt `config/auto_merge.json` → `amp.load_rules()`'s existing `ASK_ALL` fallback is used, with the threshold read from it defaulting to **3** (matching `config/auto_merge.json`'s actual `new_top_level_per_week`), not the wrong hardcoded `2`.
15. **No-test-reason surfaced, not just counted** (the ticket's own "What to build" line, missed by both prior attempts) — `check_test_skips`'s `detail` includes the actual `reason` text for at least the most recent skip(s), not only a count.
16. **Shared fetch, meaningfully asserted** — `check_all` makes exactly one `gh pr list` call per repo (not two), verified by counting mock invocations — replacing the previous `len(...) >= 0` test that could never fail.
17. **Integration** — `health_checks.run_all()` (real, with only the network/SSH-bound *siblings* stubbed — `check_github_budget`, `check_gh_gate`, `check_ticket_failure_streaks`, `check_missing_profiles`, `check_machine_reachability`→entries incl. one unreachable per test 2, `discover_launchd_jobs`→`[]`) includes all four `quality:*` ids with correct severities, and their numeric values land in `mr.compare`'s `health-monitor` snapshot via the real (unstubbed) `qc.check_all()` and `record_anomaly_metrics`.

Every existing test that currently asserts nothing meaningful is rewritten, not kept: the fails-closed test no longer accepts `("green","yellow")` (must be exactly `"yellow"` for the non-git case); the `.git`-exclusion test no longer uses `"1 file" in detail or result["detail"]`; the `rules_path` test checks the resolved *threshold* (`3` vs. mocked `5`), not just the check's `id`; `test_check_all_shared_pr_fetch_per_repo` asserts an exact call count, not `>= 0`; `test_run_all_includes_quality_checks` actually calls `run_all()` and asserts on its output, not `pass`; the "independent scoring and core check" test asserts `severity`, the `extra_core` classification, and the independence of the two lists, not just `len(results) == 1`; every `test_check_all_*` passes `tmp_path`-scoped `log_path`/`repo_path`/`rules_path` so none of them touch the real `~/.claude/logs` or `~/.agents`.
