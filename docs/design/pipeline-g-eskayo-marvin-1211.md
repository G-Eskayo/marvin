### Corrections to the prior attempt

1. **The "re-pull 14b/7b" decision was wrong, and I verified why.** PR #1385's design doc pre-ticked "re-pull qwen2.5:14b/7b," citing it as "pre-approved per #563's thread." I read #563 itself: on 2026-10-21 **the owner approved *deleting* those models to free disk** (not restoring them), and #563's own "What to build" says to make the registry/health **not report the deleted models as present** and to fall back to a stated alternative — the opposite of what PR #1385 assumed. #563's latest comment (2026-11-10) also says this is "MARVIN's research... not an owner question," due M3 (2026-11-27) — i.e. #563, not #1211, owns the tier choice. So this ticket must not silently restore 13.7 GB the owner deliberately freed. I'm presenting this as a real, un-pre-ticked Decision below (see decisions-format.md: pre-ticking is only for an answer the owner already gave — this one wasn't).
2. **The aggregation rule for "missing" was self-contradicting**, and the prior PR's own code review caught the symptom (`lib/health_checks.py:184`) without the design doc ever getting fixed: its rule was "any machine that can't be queried blocks the yellow (amber) verdict, forcing `unknown` instead." On a fleet where any one macOS box simply never runs Ollama, that machine fails to connect *forever*, so the check can never go amber — defeating AC2. Fix: a machine that can't be queried is reported `unknown` **for that machine** (satisfies the ticket's own break-it case), but it must not veto an otherwise-conclusive finding from the machines that *did* answer. Overall `unknown` only when **zero** machines answered at all; `yellow` when **at least one** machine answered successfully and the model is absent there and everywhere else that answered.
3. Minor, already-identified-by-review fixes I'm folding in rather than re-discovering: use `machine_profile.remote_macs()` not `remote_devices()` (skip the Linux pull-only node, which doesn't run Ollama — ADR 0069); validate the remote JSON is actually a list before trusting it (a dict must count as "couldn't measure," not be silently iterated); drop the redundant outer `try/except` around a function that already catches everything; drop `normalize_model_name()` (literally an unused identity function — Colton check: delete rather than force a use for it) and keep matching logic inside `model_present()`, which already does it correctly.
