## North-star fit

**Reuses before adding anything new:**
- The existing local-trigger channel (`startRefreshServer` / `/refresh` POST, `dashboard/electron/main/refresh_server.js`, already consumed by `lib/marvin_show.py` and `webhook-server/merge.js`) is extended with one more topic (`update`) instead of inventing a new IPC transport — same precedent as the existing `'mr'`, `'merge-host'`, `'merge'` special-cased topics in `dashboard/electron/main/index.js`'s `startRefreshServer(...)` callback (~line 1426-1443).
- `lib/dashboard_rebuild.py`'s `decide()` (pure function / `main()` does I/O split) and its `FAILED_FILE`-style presence/absence flag in `~/.claude/logs/` are the template for the new `demo_hold` fact and flag file — no new cross-process state convention invented.
- `dashboard/electron/main/show_bounds.js`'s `createBoundsStore` (atomic tmp-file-then-rename JSON store) is the template for any new small persisted-state module; `lib/merge_server_wait.py`'s pure `decide(running, waited_s, bound_s)` + bounded-poll `main()` is the template for serializing two rebuilds (needed for the "merge twice in a row" break-test — this gap exists in today's code too: `webhook-server/merge.js`'s direct spawn of `rebuild_and_install.sh` never checks `rebuild_running` the way `dashboard_rebuild.py`'s `decide()` does).
- `powerMonitor`/window `blur`/`focus` events plus the debounce-timer idiom already used in `dashboard/electron/main/triggers.js`'s `createTriggerHub` (single-shot `setTimeout`, cleared and re-armed, never a recurring interval) are reused for the "idle and unfocused 10 minutes" auto-restart — this avoids adding a polling loop, which `dashboard/test/polling_guard.test.js` would catch and which CONTEXT.md's "Triggers over polling" section forbids outright.
- `electron.vite.config.js`'s existing `define` config (currently empty use) is reused to bake a build SHA into the main-process bundle at build time, so the signed app never needs a Resources file edited *after* signing (which would invalidate the signature the script already works hard to keep valid).
- Decisions.jsx's own exported pure helpers (`initialDraft`, `changedAnswers`) are reused/extended, not re-implemented, for the Decisions draft-restore logic.

**Why this is the simplest sufficient approach:** no auto-updater library, no new transport, no polling anywhere new; the only genuinely new pieces are (a) a staged-build-beside-the-running-one directory on disk, (b) one new small Electron module (`app_update.js`) that is a pure-decision-core-plus-thin-I/O module exactly like the three existing ones it's modeled on, and (c) one small generic `localStorage` wrapper reused at 4 call sites (App.jsx's tab, Support's draft, the ticket-reply draft, Decisions' draft) — which clears the "don't abstract for two call sites" bar.

**Where it spends/saves:** spends a little extra disk (one staged `.app` copy beside the installed one, cleaned up after each swap) and a few bytes of `localStorage`; saves the 9 s cold-boot + context loss on every merge, saves repeated identical rebuilds while a build sits staged awaiting Restart (new `staged_built_ts` check prevents re-rebuilding the same commit every 30 min), and keeps today's demo from being interrupted at all when demo-hold is on (CPU/time saved, not spent).

**Leaves the user more capable, not more passive:** this removes an involuntary interruption (lost drafts, lost place) without taking away any choice — Gil still decides when to restart (banner), can hand that decision off safely when away (idle rule), and can pause the whole mechanism by hand before anything risky (demo). Nothing here automates a judgment call that was his to make.

**Pre-existing drift noticed while reading the touched code:** `CONTEXT.md:864-866` currently says settle is "15 min" and the app rebuilds once ">=1h behind" — the actual code (`dashboard_rebuild.py`) has used a 2-minute settle and "any staleness" since #443. I'll correct this stale sentence in the same edit that updates the "drops unsaved in-tab edits" trade-off note it sits next to.

**One placement call made without asking (not a product decision, so no Decisions entry):** there's no Settings tab anywhere in the dashboard today, and this ticket doesn't ask for one. The demo-hold switch needs to be reachable *before* anything is pending, so I'm putting it as an always-rendered small control in the same new banner component that shows "Update ready" (mounted in `App.jsx` beside `ActivityBanner`), not inside Health or a new tab. Noting this plainly rather than inventing a Settings surface.

## Tests first (one per break-it case, plus misuse the ticket's list didn't name)

1. **Merge twice in a row while the app is open → one prompt, the second build wins.** `lib/tests/test_rebuild_script.py` (or a new `test_rebuild_wait.py`, modeled on `merge_server_wait.py`'s `decide(running, waited_s, bound_s)`): a second invocation that finds one already running waits (bounded) rather than racing a concurrent `npm install`/`build:mac`, then builds against the then-current `origin/main` so the later merge isn't dropped. Plus a self-exclusion test so the wait helper doesn't pgrep-match its own caller's shell (the "pkill -f self-match" bug class already in memory) — assert excluding `--exclude-pid $$` is honored. Electron-side: pinging topic `update` twice with different `sha`s replaces one `pendingUpdate` value, never queues two; the banner-ready IPC payload reflects only the latest sha.
2. **Type a draft, trigger a rebuild, choose Restart → the draft is still there.** `dashboard/test/decisions.test.js`, a new `dashboard/test/support_draft.test.jsx`, and a new `dashboard/test/ticket_reply_draft.test.jsx`: a draft written to the new `localStorage` wrapper survives a full unmount/remount of the component (simulating relaunch), is scoped per `repo#number` (a draft for ticket A never leaks into ticket B's panel), and is cleared only after a successful send/submit, never on a failed one.
3. **Kill the app mid-rebuild → the next launch still works (no half-deleted bundle).** `lib/tests/test_rebuild_script.py`: the live `/Applications/MARVIN.app` is never `rm -rf`'d or overwritten during build/stage (assert the build writes only into `dist/` and a sibling `.staged` path, never `$DEST`, until an explicit swap step); the swap step itself uses two atomic renames with a temporary backup name, and a new pure-function test (`app_update.test.js`) asserts that if `$DEST` is found missing with a `.old.*` backup present at startup, the backup is restored before anything else runs.
4. **Demo-hold is on → nothing happens at all.** New `lib/tests/test_dashboard_rebuild.py` cases: `decide()` returns `skip, "demo hold is on"` before any other reason is even considered, and a new bash-script test asserts the demo-hold flag file is checked before `git`/`npm install`/`npm run build:mac` ever run (no CPU/network spent). Also: turning demo-hold off mid-cycle is picked up by the very next check (no stale "last attempt" blocking it, matching the existing "only failures back off" rule).
5. **A build already staged, waiting for Restart, isn't rebuilt again for the same commit.** New `test_dashboard_rebuild.py` case: `decide()` takes a `staged_built_ts` fact and skips ("installed or staged app is current") when `max(app_built_ts, staged_built_ts) >= dashboard_commit_ts`; a *newer* commit than the staged one still triggers a rebuild that overwrites the stale `.staged` copy.
6. **Idle+unfocused auto-restart never fires while the app is actually in use, and never polls.** `app_update.test.js`: the 10-minute timer only arms on the window's `blur` while an update is pending, is cancelled on `focus`, and — critically — is a one-shot `setTimeout`, never a recurring one; run `dashboard/test/polling_guard.test.js` against the new file to confirm it adds zero `interval`/`timeout-loop` findings (no allowlist entry needed). At fire time, a single point-in-time `powerMonitor.getSystemIdleTime()` check must also be ≥600 s (guards against "window lost focus because of a transient dialog" false positives) before the swap runs.
7. **Build-SHA shown once, never again.** `app_update.test.js`: the "updated to `<sha>`" announcement fires only when the running SHA differs from the last-recorded one in the marker file, and is never shown again after the marker is updated — including across a *manual* quit/relaunch that wasn't triggered by this feature at all (any SHA change at boot counts).
8. **Misuse not named in the ticket:**
   - Corrupt/missing `localStorage` entry (bad JSON, quota exceeded, private-mode throw on write) never crashes a component — the new `persisted_draft.js` wrapper fails closed to the given fallback.
   - The refresh server's `/refresh` endpoint receiving a malformed or empty body for topic `update` (no `sha`, `sha` not a string) is treated as "ready, SHA unknown" rather than throwing, consistent with `refresh_server.js`'s existing defensive JSON parsing.
   - `rebuild_and_install.sh` killed *during the swap itself* (not just during build): the two-rename sequence means `$DEST` is never simultaneously absent-and-unrecoverable; test asserts the `.old.*` backup naming makes this detectable and self-healing on the next script run.
   - Wrong permissions / build never signed (no identity on this Mac, as already handled today): staging and the swap must still work with an ad-hoc signature, exactly as today's fallback does — existing `test_rebuild_script.py` coverage for that path must still pass unmodified.
   - The app not running at all when a build finishes: swap happens immediately (no banner, no one to show it to), then the app is launched fresh — existing `pgrep`/`open -a` check still applies, just moved to this branch.
