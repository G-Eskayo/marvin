## North-star fit

**Reuses, verified by reading the files on disk (not the repo's own copy — `~/Developer/portfolio-website-updater`, the separate repo these tools operate on):** the `research` role already exists in all four content templates (confirmed in `templates/content/app-product.json`: `role: "research"`, `heading: "Research behind it"`, `required: false`, `evidence: ["callout"]`, positioned between `status` and `built-with`). The `.longform-callout` component (`templates/components/longform-callout.html`) is already styled in `deploy/longform/longform.css`, and already has a real precedent in production copy: `content/longform/distributed-llm-inference.json`'s `lead_html` wraps a cluster of stat facts in one `<div class="longform-callout">…</div>`. `lib/portfolio_content.py`'s `coverage()`/`findings_for_evaluation()` already walk a template's `sections` generically — confirmed by reading `lib/portfolio_content.py:69-86` and its tests. The only gap is `evidence_in()` (`lib/portfolio_content.py:53-66`): it has no branch for a `.longform-callout` div, so today a research section would fail its own template's evidence check no matter what it contained. That one `if` branch is the entire integration surface; no new checking subsystem is needed.

**What actually went wrong last time, verified by reading this worktree's state, not assumed:** `lib/portfolio_research.py` **does not exist** — `find lib -iname "*research*"` returns nothing. Every prior attempt's work (`portfolio_research.py`, its tests, `portfolio_content_additions.py`, nine `*.md` summaries) sits untracked at the repo root, and `WORKTREE_SUMMARY.md` itself says each file is "**Ready to move to:** `~/.agents/lib/...`" — the move never happened. Since there's no `pytest.ini` restricting collection, a root-level `pytest` run collects these stray `test_*.py` files too. I read them and found the real bugs, not just the file-location problem:
- `generate(repo_path, content_path, template_path=None)` takes a `template_path` parameter and **never reads it** — the section is always appended to the end of `sections`, never inserted at the template's declared position between `status` and `built-with`. The stray test file even asserts the end-append as *correct* (`test_insert_or_update_section_defaults_to_moving_to_end`), encoding the bug as a passing test.
- `generate()` returns `{}` silently when `content_path` doesn't exist instead of raising — a typo'd path fails silently instead of loudly.
- `render_research_section()` checks `entry["public"] == "Internal"` to hide — meaning anything that *isn't literally* `"Internal"` (blank, `"Draft"`, a typo) is **shown**, the opposite of the acceptance criterion "no public-use flag → treat as Internal."
- It invents `<dl class="research-entries">`/`research-caveat` markup with no matching CSS anywhere in the target repo, instead of `.longform-callout` — exactly the kind of unapproved-UI invention that fails review on sight.
- It also carries a speculative, never-wired `check_research_section()` (and two tests for it) that nothing calls — `evaluate()` was never touched to use it. It's dead code answering a question the ticket never asked.
- Two stray test files assert against `Path.home() / "Developer" / "clarity-captions"` and `Path.home() / ".agents" / "lib"` — real absolute paths that may not resolve the same way wherever the verification harness runs `pytest`, the near-certain source of the `pytest_failed` regression (2 → 5, +3 — matching roughly three bad stray test files).

This plan fixes all five, and this time actually lands the code in `lib/`/`lib/tests/`, with the root cleaned up as literally the first commit, not a to-do left for later.

**Simplest sufficient approach:** a pure parse → render → insert pipeline, no network calls, taking `repo_path` and `content_path` exactly like every other `portfolio_*.py` tool. `generate()` derives the template path itself from `content_path`'s own repo layout (`content/longform/<slug>.json` → `../../templates/content/<content_type>.json`), so there's no second path argument to forget to use — removing the dead-parameter bug by removing the parameter, not by remembering to read it. Rendering reuses the one component the templates already point at. I'm cutting `check_research_section()` entirely: no acceptance criterion asks for a missing-section warning, and a function nothing calls is exactly what the Watts check flags — output nobody consumes.

**Tokens:** one new ~150-line module plus one `if` branch, reusable by every future project with an evidence log (`lib/portfolio_research.py <repo> <content.json>`) instead of hand-written sections each time. Smaller than the previous attempt's surface (no dead parameter, no unwired checker, no bespoke CSS to invent and justify).

**Capability:** no bearing on phone-OS. For north star 3, it makes Gil's research-backed reasoning checkable by any reader and structurally prevents the one failure mode he named (never claim a font improves reading, E5) rather than relying on someone remembering to write it that way by hand.

### layout: How should the shown research entries be presented in the "Research behind it" section?
- [ ] A: One shared `.longform-callout` box holding all shown entries as a list — matches the one real precedent on the site today (`distributed-llm-inference.json`'s lead, which bundles several stat facts into a single highlighted box) and keeps the section visually calm. This is the build default if unanswered.
- [ ] B: One `.longform-callout` box per entry — each research point gets its own highlighted callout, more like a row of citations, higher visual weight per entry but more boxes on the page.
