**Simplest sufficient form:** every gap in the ticket's table is a guard that already exists and already decides something — the fix is closing the hole (record + look it up), not new machinery. No new alert channel, no new polling loop, no new daemon.

## Tests I'll write first

One per "How we'll try to break it" case, plus the misuse cases it didn't spell out:

1. **Missing file / unreadable permissions / malformed JSON** for the guard-reading state file itself (`guard_reading.record`/`status` never raises, treats a corrupt state file as "no history," not a crash).
2. **A probe that hangs** — N/A at the `guard_reading` layer (it never calls a probe itself, only records a bool a caller already computed); covered instead at each call site's existing timeout (already present in every guard read — no new test needed there).
3. **A CLI not on PATH** (launchd PATH) — `task_dispatch.tailscale_online_hosts_or_none()` returning `None` (today, silently empty-set) is recorded as unreadable; after ≥2 consecutive readings the Health row for `task_dispatch:tailscale` is yellow; replay #889's shape (unreadable for 4 simulated days) and assert it reaches **red** at the 2h mark and stays red (not re-alerted every sweep beyond the daily reminder `alert_on_change` already gives).
4. **The same reading flapping between readable and unreadable** — a sequence `ok, bad, ok, bad, ok` (single-blip flaps) never flips the guard's recorded state (the 2-consecutive-reading debounce absorbs it): one episode is logged, not five.
5. **A guard added later without a table entry** — a test that scans `lib/*.py` for every `guard_reading.record("<name>"` call site and asserts every name is a key in `GUARD_POLICY`, and every `GUARD_POLICY` key has at least one real call site (symmetric: the table can't drift stale either way). Adding a new `guard_reading.record("new:thing", ...)` call with no table entry must fail this test.
6. **A remote Mac unreachable over ssh** — `task_dispatch._read_remote_dispatch_state` on an ssh failure is recorded unreadable (not silently `{"busy": False}`); same for `_read_local_dispatch_state` on a corrupt/missing state file.
7. **Malformed task records** — one corrupt `*.json` among several good ones in `dispatch_concurrency._read_task_records` and `model_queue._read_task_records` is recorded unreadable *and* the good records still load (undercounting is visible, not silent).
8. **Dependency failing: disk unreadable** — `disk_triggers.preflight(free=lambda: None)` now **refuses** (flips the existing `test_preflight_fails_open_when_free_space_cannot_be_read` to assert `ok is False` with a message that says "couldn't read free space," distinct from the "disk is low" wording) and records `disk:preflight` as unreadable+closed.
9. **Dependency failing: memory unreadable** — `memory_guard.check(level=None)` now refuses (flips `test_an_unreadable_level_is_none_so_it_never_blocks` to assert `ok is False`), with a distinct "couldn't read memory pressure" message.
10. **Dependency failing: merge-gate disk floor unreadable** — `dashboard/test/gate_low_disk.test.js`'s and `merge.test.js`'s "fails open when free space cannot be read" tests flip to "fails closed."
11. **`failure_breaker` record_failure raising** (bad log permissions, disk full) inside `run_ticket._feed_breaker` — today silently `print`s to stderr and is never seen again; test that it's recorded as an unreadable guard reading instead (or in addition).
12. **Repeats/concurrency**: two processes calling `guard_reading.record` for the same guard name at once never corrupt the state file (atomic write, same tmp+`os.replace` idiom already used by `mr_notification._write_memory`/`main_health._write`).
13. **Wrong permissions / stale state**: a `guard-readings.json` left over from a guard that no longer exists doesn't grow forever and doesn't show on Health (only currently-registered `GUARD_POLICY` names are read).
14. **A person's mistake**: calling `guard_reading.record` with an unregistered name raises loudly in dev/test (caught by test #5), not a silent no-op in production (unknown names still get *recorded and shown*, just fail the coverage test so they get a table entry).
15. **Verify-fails-without-a-test-change check**: the two flipped fail-open→fail-closed tests above are exactly where "code changed, test didn't" would be caught — both are being edited.
