## Grounding: why the last attempt regressed (verified by running the suite, not guessed)

I ran `pytest lib/tests/test_failure_breaker.py lib/tests/test_run_ticket.py lib/tests/test_health_checks.py lib/tests/test_project_profile.py lib/tests/test_ticket_agents.py` against the exact uncommitted diff already in this worktree: **35 failed, 269 passed** — reproducing the reported regression exactly. I traced every failure to one of four root causes:

**1. ~26 of 35 failures: stale tests never migrated when `_consecutive_failure_streak` was deleted.** `run_ticket.py` correctly replaced the old GH-comment-scanning counter with `failure_breaker.ticket_streak`/`should_hold`, but ~22 call sites across `lib/tests/test_run_ticket.py` still do `monkeypatch.setattr(rt, "_consecutive_failure_streak", lambda *a: 0)` to neutralize the old counter while testing unrelated behavior (comment posted, claim released, run_id threading, etc.) — these now raise `AttributeError` on an attribute that no longer exists. Two more tests (`test_consecutive_failure_streak_counts_trailing_failure_comments`, `test_consecutive_failure_streak_resets_on_a_human_comment`) directly test the deleted function and must be deleted outright, not fixed. Three more (`test_park_stuck_ticket_removes_ready_for_agent_label`, `test_parking_adds_needs_info_before_removing_ready_for_agent`, `test_the_park_comment_carries_the_real_cause_and_the_findings`) assert the *old* `needs-info`/"remove needs-info, add ready-for-agent" wording that `_park_stuck_ticket` intentionally no longer produces (it now uses `hold`). These need real rewrites to assert the new `hold` + signatures + `Revisit by:` contract, not deletion — they're testing a real, still-needed behavior (label-before-remove ordering, comment contents), just the old assertions.

**2. A genuine functional regression: the park comment lost the failure's full cause.** The old `_park_stuck_ticket` had a dedicated `**Why it's stuck:** {reason[:500]}` line — added originally (per its own comment, "#133 got needs-info for an unrelated template gap, the real cause lost") specifically so a parked ticket's comment always carries the real cause. The new version deleted that line and only folds `reason[:80]` into the `Revisit by:` line. For short reasons this is invisible (the 80-char cap doesn't bite), which is exactly why `test_a_park_without_findings_still_says_why` still passes by coincidence — but `test_a_huge_reason_and_many_findings_are_capped` (reason = 9000 chars) catches it: the full 500-char cause is gone, only an 80-char fragment survives. **Fix: restore the dedicated `Why it's stuck` line (500-char cap, unchanged from before) as well as the new signatures/Revisit-by lines — additive, not a replacement.**

**3. A real correctness bug in the instant-park rule: reusing `signature()`'s digit-stripping causes false "identical failure" matches.** `signature()` (`lib/failure_breaker.py:57-58`) strips all digits before hashing, by design, so the cross-ticket breaker can match "the same failure across different tickets" despite incidental numbers (line numbers, PIDs). Reused for `should_hold`'s new "last two signatures equal → park instantly" rule, this causes two **textually different, unrelated** failures to collide whenever they differ only by a digit: I verified `signature("reason1") == signature("reason2") == "other:reason"` directly. Two of the prior attempt's own tests (`test_should_hold_respects_custom_threshold`, `test_should_hold_does_not_park_on_count_less_than_threshold`) fail precisely because of this — they use `f"reason{i}"` fixtures that collide. This isn't just a test bug: in production, two failures that happen to only differ by a line number or an iteration count would wrongly trigger an instant park at attempt 2, defeating the configured threshold. **This needs an owner decision (below)** since it's a real tradeoff, not a one-line fix.

**4. 3 health-check test failures: `monkeypatch.setattr(hc.subprocess, "run", fake_run)` doesn't work for these two specific functions.** `check_ticket_failure_streaks`/`check_held_by_retry_storm` both declare `run=subprocess.run` as a **default argument**, evaluated once at module-def time and bound to the real `subprocess.run` object — patching the `subprocess` module's `run` attribute afterward does not change that already-bound default. (This is a real, pre-existing project pattern — `scanner_role.py`, `code_review_gate.py`, `machine_resources.py` all use the same `run=subprocess.run` idiom — but the new tests used the *other* convention that's common elsewhere in `test_health_checks.py`, for functions that call `subprocess.run` inline rather than via a captured default.) I confirmed this directly: the fake never gets called; the real `gh` resolves through the suite's global `_no_real_github` fixture (conftest.py) to a fake binary that exits 1, so `claimed`/`held` silently come back `[]`. **Fix: tests must call `hc.check_ticket_failure_streaks(run=fake_run)` / `hc.check_held_by_retry_storm(run=fake_run)` explicitly.** Two more tests in the same new block (`test_check_held_by_retry_storm_green_when_no_held_tickets`, `..._green_when_held_no_active_streak`) currently pass *only by this same accident* (empty list coincidentally matches "green") — not in the 35, but not real coverage; fixing them alongside is in scope since I'm already in this block.

**Separately, 3 of the new `test_failure_breaker.py` tests have incorrect expectations, not implementation bugs** — `ticket_streak`/`signature()` behave correctly; the test authors' assumptions didn't match: (a) `..._falsy` test assumed an empty-reason failure produces a falsy signature, but `signature("")` returns `"other:"` (truthy) — a falsy `sig` only occurs for a malformed/legacy record missing the `sig` key entirely, which needs a raw-JSON-line fixture, not `record_failure("")`; (b) `..._non_deduplicated_signatures` expected `"other:same"` but `signature("same reason")` is `"other:same reason"` (no word-truncation happens, only a 60-char cap); (c) `..._excludes_future_records` never actually records a future failure, so its own assertion (`count == 1`) contradicts its two genuinely-past fixtures (`count == 2`) — needs a third, future-timestamped record added.

I did **not** find the "8 fewer pytest_passed" to be cross-test pollution via a shared real log file — `lib/tests/conftest.py:93-96` already has a suite-wide `_isolate_failure_breaker_log` autouse fixture (function-scoped, fresh `tmp_path_factory.mktemp` per test) that pre-dates this ticket. That part of the safety net is already solid and needs no new work.

`lib/project_profile.py`, `lib/tests/test_project_profile.py`, `lib/ticket_agents.py`, and `lib/tests/test_ticket_agents.py`'s diffs are **already correct and already passing** — no changes needed there. The `hold` skip in `plan_triage` and `failure_threshold` validation are good work; keep as-is.

## Decisions

<!-- marvin:decisions -->
### instant_park_equality: Basis for the "two identical failures in a row" instant-park rule
`signature()`'s digit-stripping (built for the cross-ticket breaker's cross-ticket matching) causes two **different** failures that merely share a non-numeric shape (e.g. "reason1" vs "reason2", or two stack traces differing only by line number) to look identical to `should_hold`, triggering an instant park after only 2 attempts instead of the configured threshold. Confirmed directly: `signature("reason1") == signature("reason2")`.
- [ ] A: Keep using the existing (loose) `signature()` for the instant-park comparison too. Simpler, no new code path, but tickets whose failures differ only by incidental numbers get parked unusually fast — in the ticket's own spirit ("retrying can't help"), arguably a false positive, but still fails toward *more* caution, never toward more retries.
- [ ] B: Compare the raw (300-char-truncated) failure `reason` string instead of the canonicalized `signature` for the instant-park check only. `ticket_streak` already returns an ordered, non-deduplicated signature list; add a parallel ordered `reasons` list and have `should_hold` compare `reasons[-1] == reasons[-2]`. Threshold counting, Health's display, and the cross-ticket breaker are untouched. Fixes the two failing tests by correcting the implementation, not just patching their fixtures.

I'll build against **B** (lower blast radius — doesn't touch the already-shipped cross-ticket breaker's matching behavior, and is what the prior attempt's own test authors evidently expected) unless told otherwise.
