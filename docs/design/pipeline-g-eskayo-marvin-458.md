## Decisions

### quarantine-placeholder: Does a quarantined digest count as "not produced" (and trigger a MacBook rebuild)?
- [ ] A: Yes — treat a quarantined digest as not-produced. The MacBook rebuilds as fallback, risking a second same-day quarantine entry (one of the two incidents ADR 0067 exists to stop). Implemented as a precise match against the known quarantine marker text (`"approve/modify/deny"` + `"quarantine.md"`), not the over-matching `"_Quarantined" in stripped` substring the denied attempt shipped.
- [ ] B: No — a quarantined digest is "produced, held for review." The MacBook does nothing; a quarantined day stays quarantined rather than getting a second attempt. **This is what the code in this PR implements by default** (simplest fix: `mini_output()` drops the quarantine special-case entirely — any non-empty remote content counts as produced), since it's the option consistent with this ticket's own motivation (stop duplicate runs/entries). Pick A instead if you want the MacBook to retry on a quarantine.

### cross-machine-merge-cleanup: What happens to `cross_machine_merge.py`'s now-dead LLM-merge step for daily-digest/research-digest?
- [ ] A: Remove the `daily-digest`/`research-digest` iteration from `run_merge_authority()`'s loop now, since under this ticket there's never a second same-day file to merge.
- [ ] B: Leave it as a harmless no-op (it already skips gracefully when the remote file doesn't exist) and clean it up in a later ticket. **Left as-is in this PR** — `cross_machine_merge.py` isn't in this ticket's "What to build," and touching it would widen an already multi-file diff for a file that fails safe today.

## Tests to write first

All new/changed tests use `tmp_path` and `monkeypatch` for every path constant touched (`BRIEFS`, `DIGEST_DIR`, `OUT_FILE`), per the ticket's explicit instruction — never the real `~/.claude` (root `conftest.py`'s write-guard would fail the test by name anyway if one slipped through). SSH itself is faked (`ssh_cat` monkeypatched) since there's no second real Mac in this environment; the *content rules* (what counts as real vs. placeholder vs. corrupt) are tested against the literal strings the real code produces, never a mock that could hide a mismatch. There is no outward-facing/untrusted-input surface in this ticket (no form, endpoint, or external payload — `remote_relpath` is always a hardcoded f-string built from `today`, never user input), so the standard injection/XSS/auth-bypass attack list doesn't apply; this is noted rather than skipped silently.

1. **Mini down all morning** — `ssh_cat` returns `None` for every call; the fallback script builds exactly once and logs "covered for the Mini" (one test per job: `daily_digest.main`, `research_digest.generate` via `run_colony.main`, `morning_brief.cli_build`).
2. **Mini already produced it** — `ssh_cat` returns real content; fallback does nothing, logs nothing new, and (for research-colony specifically) never calls `source_monitor.main()`/`correlate.correlate()` — asserted via a raise-on-call sentinel, the same pattern `test_daily_digest.py::test_main_short_circuits_when_out_file_exists` already uses.
3. **Mini late, finishes after the fallback started** — pre-write re-check returns real content where the pre-build check had returned `None`; the fallback discards its own result (never calls `write_text`), and logs that Mini's result won. One test per job.
4. **Mini's output is a failure/quarantine placeholder** — `daily_digest`'s `"(claude call failed:"` prefix and the exact quarantine sentence; with Decision B implemented, assert these are *not* treated as empty (quarantine counts as produced — fallback does nothing) while a genuinely empty or whitespace-only remote file still counts as not-produced.
5. **Clock skew / MacBook asleep through the deadline** — invoke with `now` several hours past deadline; assert it still runs the check-and-build-once path, not "too early" and not a second run later the same day (idempotency guard catches the second firing).
6. **Both machines run the fallback check at the same moment** — `is_primary()` is False on at most one of two simulated registry entries (`kind="desktop"` vs `kind="laptop"`) — mutually exclusive by construction, not by timing.
7. **Not yet past deadline** — invoked at the *earlier* `StartCalendarInterval` time; returns immediately with no SSH call at all (not even a failed one) and no fetch/correlate call for research-colony.
8. **Bad/malformed remote content** — `ssh_cat` returns empty string, binary garbage, or a truncated/non-UTF8 payload; the "is this real" predicate treats it as not-real (triggers fallback) rather than crashing.
9. **Dependency failure: SSH unreachable mid-build (late re-check)** — `ssh_cat` raises/returns `None` on the *late* re-check specifically (not just the early one); the fallback still writes its own result rather than crashing or hanging.
10. **Repeats/idempotency on the primary, including the actual bug found** — call the Mini's own path at both its scheduled times the same day (08:30 then 09:30 for daily-digest; **09:00 then 10:00 for research-colony, the exact case defect #3 broke**): second call is a fast no-op, `source_monitor.main`/`correlate.correlate` are never called the second time (raise-on-call sentinel), and the built-by stamp isn't re-written with a different timestamp.
11. **Wrong/unrecognized machine** — a registry entry with `kind` missing or some third value (neither `"desktop"` nor `"laptop"`); `is_primary()` fails closed to `False`, and `mini_output()` skips that entry rather than matching it.
12. **Huge/malformed local digest file** — `mini_output`'s "is this real" check against a multi-MB and a non-UTF8-decodable remote payload; degrades to "not real" rather than hanging or raising.
13. **`past_deadline()` timezone correctness (the actual must-fix, not a weaker stand-in)** — same wall-clock instant expressed in `America/Los_Angeles` and `America/New_York`, via the new `tz` parameter (not host-local `astimezone()`), asserted to give identical, zone-correct answers regardless of the machine running the test. Plus one test for the corrected midnight-wrap boundary (`usual_hour=23`): exactly at the usual time → not past deadline; 45 min later (post-midnight) → not past deadline; 75 min later → past deadline.
14. **`ssh_cat()` and `is_stationary()` directly** (currently untested except through mocks in `test_job_ownership.py`) — new `lib/tests/test_machine_profile.py`: non-zero exit → `None`; timeout → `None`; exception → `None`; successful read → stdout; `is_stationary()` delegates to `load_or_build().get("mobility_class")`.
15. **Health check (AC4), happy path** — a `.built-by.json` naming `mac-mini`/`primary`; `check_brief_owner()` returns `"green"` naming the machine and role. A `role="fallback"` stamp returns `"yellow"` (per the review's "grade on primary vs fallback" instruction), not red — fallback working as designed isn't a failure.
16. **Health check (AC4), the actual crash the review found** — call `check_brief_owner()` with no `path` argument at all (the exact call shape every real Health run uses) and confirm it does not raise `TypeError`. Separately: non-dict JSON and a non-ISO `at` field are "corrupted," not a crash — and since grading no longer subtracts `at` from `now`, there's no `TypeError` path left to test around.
17. **Health check (AC4), no brief yet** — before the deadline: `"yellow"` ("no brief built yet today"), not red (too early is normal). Past the deadline with still nothing: `"red"` (both machines missed it), using `job_ownership.past_deadline` for consistency rather than a second, unrelated age threshold.
18. **`JOB_PLACEMENT`/`evaluate_job_placement`** — already covered by the existing, unmodified `test_job_placement_flags_missing_stray_and_unplaced_jobs` (it derives `laptop_jobs` dynamically from the live `JOB_PLACEMENT` dict, so `"morning-brief": "both"` is already exercised with no new test needed; confirmed by reading the test, not assumed).
19. **Full-suite vs. standalone import check** — run each new/changed test file alone (`pytest skills/research-colony/scripts/tests/test_run_colony.py`) and as part of the whole suite, to catch the `Path.home()/".agents"/"lib"` import-shadowing fragility described above if it ever stops resolving by luck.
