**Reuses before adding anything new:** this revision keeps the whole previous design's reuse story (`lib/scanner_role.py::is_primary()`/`should_scan()` → `lib/brief_fallback.py::should_run()`, `lib/machine_profile.py`'s registry helpers, `lib/task_dispatch.py::SSH_OPTS`) — `lib/brief_fallback.py` and its test file are already correct in this worktree (I re-verified `_infer_remote_path`/`read_remote` directly; both defects from the last-but-one review round are fixed) and need **no further edits**. For this round's three fixes specifically, each one reuses something already in the file it touches rather than adding a parallel mechanism:
- The brief's missing-research/missing-digest gap is detected by making `_digest_idea()`/`_research_idea()` (`lib/morning_brief.py:138-149`) raise when today's file genuinely doesn't exist yet, so the **existing** `gather()` try/except and `missing` list (`lib/morning_brief.py:206-216`, already rendered into a `## Gaps` section) reports it — not a new marker file or a second gap-detection path.
- The brief-builder health check's new "not due yet" state reuses `brief_fallback.past_deadline()` (`lib/brief_fallback.py:130-140`) directly instead of a second grace-period calculation.
- The schedule fix is a pure value correction back to the one relationship (`usual + 1h`) the ticket itself specifies, already implemented once correctly for daily-digest (08:30/09:30) and research-colony (09:00/10:00); morning-brief's own 09:15/10:15 pair was the one instance that broke that reused relationship, confirmed by `git diff main -- config/launchd/com.marvin.morning-brief.plist`: the prior attempt changed the Mini's schedule from **45** to **15** minutes past 9, discarding the exact 45-minute-after-colony-starts buffer the pre-ticket, known-working schedule had.

**Simplest sufficient approach:** three one-line-scale fixes (two schedule values + a default-parameter match, one CONTEXT.md correction, one test-isolation fix) plus one small, directly-caused follow-on (the gap must be rebuildable, not just rarer) and one bug I found independently while fixing the third item (an analogous test in `test_run_colony.py` has the same early-return-masks-the-TOCTOU-path defect, worse: it also leaks to the real `~/.claude/chroma`). No new files, no new abstraction — every fix lands inside a file this ticket already touches.

**Where this saves/spends tokens:** no change to the token story already established (halves model calls for these three jobs); this round spends zero extra tokens — it only fixes two real races and one test that wasn't testing what it claimed.

**More capable, not more passive:** `brief:builder` stops reporting a false "yellow" every single morning before the brief is even due (a trust-eroding false signal the review's notes called out), and a degraded brief (built before its feeds existed) can now actually self-heal instead of being silently stuck for the rest of the day.

**Correcting the ticket's/prior doc's own claims:** CONTEXT.md:1470's "Cross-machine merge runs after all three" is factually wrong per `docs/adr/0014-research-colony-event-driven-merge-trigger.md` and `skills/improve/scripts/check_and_trigger_merge.py`: merge is event-driven (fires right after whichever machine's digest/colony run finishes last), concerns only daily-digest/research-colony output, and has nothing to do with the brief.
