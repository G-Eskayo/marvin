## North-star fit

**Reuses before adding anything new** (re-verified against the files as they stand in this worktree today, not assumed): the uncommitted draft already reuses the right things — `scanner_role.is_primary()`'s pure prefix check (`lib/scanner_role.py:27-28`), `machine_profile.remote_macs()` (`lib/machine_profile.py:192`), `task_dispatch._tailscale_online_hosts()` (`lib/task_dispatch.py:53`), and `cron_health.JOBS`/`health_checks.JOB_PLACEMENT`'s existing tables. That part of the prior plan was sound and stays. This revision does **not** redesign the mechanism — it fixes concrete, verified defects in the already-written code and tests that the last attempt shipped without ever running, plus closes gaps neither prior plan caught.

**Why the last attempt regressed (root-caused by reading every touched file, not guessed):**

1. **The dominant cause of the regression.** `skills/improve/scripts/daily_digest.py:277` and `skills/research-colony/scripts/research_digest.py:103` do `import brief_fallback` **inside** `main()`/`generate()`. A function-local `import` binds the name only in that function's local namespace — it never becomes a module attribute. The new tests (`test_daily_digest.py:356,405` and `test_research_digest.py:32,72,93,112`) all do `with patch("daily_digest.brief_fallback") as mock_bf:` / `patch("research_digest.brief_fallback")`, which requires the attribute to already exist on the module (`create=False` is `patch`'s default). It doesn't, so every one of these ≥6 tests raises `AttributeError` at setup, not an assertion failure. This alone plausibly accounts for most of the 13 newly-failing tests. **Fix:** hoist `import brief_fallback` to module level in both files, next to the existing `from notify import notify` / `import marvin_launcher` lines that already do the identical `sys.path.insert(0, str(Path.home() / ".agents" / "lib"))` — matching the file's own established convention, not inventing a new one.
2. **A previously-flagged, still-unfixed defect.** `lib/tests/test_health_checks.py:1331` asserts `"No brief built yet"` (capital N); `lib/health_checks.py:1477` returns `"no brief built yet today"` (lowercase). This was identified as defect #9 by the prior design doc and never applied. Guaranteed failing test, one-line fix (fix the test, not the production string — the lowercase message is correct house style).
3. **A non-deterministic test caused by an un-mocked live call.** `lib/tests/test_brief_fallback.py:309-361` (`test_pre_write_recheck_catches_remote_only_produced_during_generation`) never mocks `task_dispatch._tailscale_online_hosts()`. `read_remote()` (`lib/brief_fallback.py:62-68`) checks that function whenever `host` isn't passed explicitly, before ever reaching the injected `run` callable. The fake hostname `"mac-mini-1.tailscale"` will never appear in a real (or absent) Tailscale status output, so `read_remote()` always returns `None` regardless of `run_mock_produced` — `decision2.should_build` can never become `False` as the test asserts. Confirmed by reading `_tailscale_online_hosts()` (`lib/task_dispatch.py:53-67`), not assumed.
4. **A schedule inconsistency nobody caught.** `skills/improve/com.marvin.daily-digest-fallback.plist` fires at **10:30**, but `daily_digest.py:278`'s own `should_run(usual_hour=8, usual_minute=30)` with the default 60-minute grace computes a deadline of **09:30** — exactly what `lib/cron_health.py:72-75`'s `JOBS["daily-digest-fallback"]` already expects. The sibling jobs (`research-colony-fallback` → plist 10:00 = `usual_hour=9` + 60min grace; `morning-brief-fallback` → plist 10:45 = `usual_hour=9,minute=45` + 60min grace) are all internally consistent; only `daily-digest-fallback` drifted an hour late, meaning a down Mini wouldn't get covered until an hour after the ticket's own "one hour after the usual time" wording promises.
5. **A real coverage gap neither prior plan named.** `skills/research-colony/scripts/run_colony.py:16-27` — the actual launchd entry point for the research-colony job — has its own `should_run()` gate, and it has **zero** test coverage. `test_research_digest.py` only tests `research_digest.generate()`'s internal recheck, not the thing the plist actually invokes. AC1/AC2 are untested at the one place that matters for the real cron job.
6. **CONTEXT.md contradicts itself, and nobody's touched the older half.** Lines 190-218 ("Orchestration shape", dated 2026-07-08) still say research-colony running independently on both Macs is "redundant *by design*, not a bug" — directly contradicted by ADR 0067 (2026-10-15) and by line 1466-1468 ("Brief owner") that this very ticket implements. A design that contradicts a recorded decision is a defect per the north-star instructions; here the *doc itself* holds two contradicting decisions about the same subsystem. Needs a factual correction, not a new Decision (ADR 0067 already settled this, after the older note was written).
7. **A design confusion that's currently masked, not test-breaking, but real.** `lib/morning_brief.py:288` and `research_digest.py:105` now call the full `brief_fallback.produced()` — which, when the local file is missing, cascades into a live registry lookup and (if a host resolves) a real SSH attempt — for their own **local** idempotency guard, on every call, including the primary's own normal write. In this repo's test harness it fails closed harmlessly (`marvin-network.json` is deliberately excluded from the test-HOME symlink allowlist in `lib/real_home_guard.py:53`, so `machine_profile._load_registry()` returns `{}` and nothing network-ish happens) — so it isn't what broke the 14 tests. But it's still architecturally wrong and wasteful in production: the primary doesn't need to ask "did someone else produce this?" before writing its own authoritative output, and `research_digest.generate()`'s plain re-entrancy check shouldn't carry remote-SSH capability either. North star #1 (least resources) and the Colton check (same principle, simpler form) both argue for separating "is this local content valid" (pure, no I/O) from "has the primary produced it, checking the network as a last resort" (only `should_run()`'s standby path needs that).

**Where it spends/saves tokens:** unchanged from ADR 0067 — once this actually lands and both plists are loaded, daily-digest and research-colony stop double-fetching/double-calling the model on a normal day. This revision spends a bit more care up front (reading every touched file, actually running the suite) specifically to stop burning a second/third pipeline attempt's worth of tokens on a regression that was knowable from the code alone.

**More capable, not more passive:** unchanged — Health already shows who built today's brief (`check_brief_builder`, `lib/health_checks.py:1467`); this revision makes that claim trustworthy by fixing the one test that currently contradicts it.
