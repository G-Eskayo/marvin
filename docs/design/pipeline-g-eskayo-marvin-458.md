## North-star fit

**What's actually here already, verified by reading it (not assumed):** this worktree already carries a substantially-built implementation — `lib/brief_fallback.py`, `lib/morning_brief.py`, `lib/health_checks.py::check_brief_builder`, `skills/improve/scripts/daily_digest.py`, `skills/research-colony/scripts/{run_colony,research_digest}.py`, three new fallback plists, and matching tests. `lib/cron_health.py::JOBS` already has `morning-brief` at `"09:45"` — both prior design docs wrongly claimed this was missing; it isn't, and my task list below does not touch it. This plan is a targeted fix of real, confirmed defects in the existing draft, not a rewrite.

**Existing pattern reused (file:function), before adding anything:** `lib/scanner_role.py:27-28,57-73` (`is_primary()`, `check_primary()`'s live-SSH-read shape) is already mirrored by `brief_fallback.py`'s `Decision`/`should_run()`. I'm additionally reusing `lib/machine_profile.py:192-196` (`remote_macs()` — already filters out non-macOS devices, written explicitly for the mac-mini-2012/Kali risk, ADR 0069) for the one new piece of wiring below, instead of the raw `remote_devices()` the current `read_remote()` lookup would otherwise need. `lib/health_checks.py`'s `_result()`/`guarded()` pattern stays as-is. No new file, no new abstraction — this is bug-fixing inside the module the previous attempts already built.

**Why simplest sufficient, with three corrections found by reading the real code (not inherited claims):**

1. **`read_remote()` is dead code — confirmed, not duplicated from any prior doc's guess.** `lib/brief_fallback.py:124-143`'s `produced()` only ever checks the local file + local `.built-by` sidecar; `read_remote()` (lines 64-89) is defined, fully tested in isolation (`test_read_remote_successful` etc.), and never called from `produced()`, `should_run()`, or anywhere else. I traced *why this matters*: `~/.claude`'s only sync mechanisms are `code_sync.py` (a curated git allow-list — `daily-digest/`, `research-digest/`, `briefs/` aren't in it, confirmed by reading `lib/code_sync.py:1-20`) and `cross_machine_merge.py`, which writes to `{day}-merged.md` (`skills/improve/scripts/cross_machine_merge.py:357-361`) — a **different filename** than the one `brief_fallback.produced()` checks (`{day}.md`). So on a normal morning the standby's local copy of `{day}.md` never exists at all, by construction — `produced()` as currently wired would almost always say "not produced" and the fallback would double-build every single day, exactly the bug ADR 0067 exists to kill. This is AC2/AC3 currently non-functional, not a style nit.
2. **No pre-write recheck in the two LLM-backed jobs — confirmed by tracing the actual control flow.** `daily_digest.py::main()` checks `produced(OUT_FILE)` *before* `call_claude()` (90-120s per its own comment, `daily_digest.py:248-251`) but never again before `OUT_FILE.write_text(...)` at line 334. `research_digest.py::generate()` has the identical gap (check at line 104, write at line 159, `marvin_launcher.launch(...)` in between). This is the literal scenario named in the ticket: *"Mini late but finishes after the MacBook started: no double brief; one wins deterministically"* — currently, whichever write lands last wins, non-deterministically, and the Mini's correct output can be silently clobbered.
3. **`past_deadline()` computes `cutoff` and never uses it** (`lib/brief_fallback.py:146-156`): it returns `True` unconditionally whenever `produced()` is False, so `health_severity()` and `health_checks.py::check_brief_builder` (lines 1450-1506) go straight to **red** the instant a file is missing, never respecting the soft/hard deadline hours in their own comments. This breaks AC4's actual signal.

All three are genuine, narrow fixes to existing functions/call sites — no new files, no new scheduling framework.

**Where this saves/spends tokens:** unchanged from ADR 0067's stated payoff (half the model calls for digest/colony once the fallback actually works) — fix #1 is what makes that real instead of nominal; fix #2 prevents a wasted LLM call's output from being thrown away by a race nobody would notice.

**More capable, not more passive:** Health gets a real green/yellow/red (fix #3), not a false permanent red; Gil stops getting silently duplicated model-call spend.

**On the verification-metrics regression handed to me** (`vitest_passed` 2164→118, `vitest_failed` 0→1, others flat/improved): I traced this to the actual issue-comment history, not guesswork. A comment on this exact ticket records: *`vitest produced no test summary (crashed or never ran): ...dashboard/node_modules/tinypool/dist/index.js:118`*, and `Glob("dashboard/node_modules")` in this worktree returns nothing — **`dashboard/node_modules` is absent in this worktree**, so vitest crashes partway through its suite. The wildly different `vitest_passed` counts across past comparison runs (118 vs 2164) are purely a function of how many files ran before the crash — zero relation to code correctness. This ticket's diff touches **no file under `dashboard/`** (confirmed: `git diff` scope above is entirely `lib/`, `skills/`, `config/launchd/`, `CONTEXT.md`). `pytest_passed` actually improved (+28) and `pytest_failed` is flat (the baseline's one pre-existing failure, unrelated to this ticket, untouched).
