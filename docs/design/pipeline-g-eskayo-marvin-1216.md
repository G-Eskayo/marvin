## North-star fit

**Reuses:** the "untrusted content in its own sandboxed surface" pattern already in this file tree — `mockup_window.js:93-103` and `show_web.js:99-109` both already run `sandbox: true, contextIsolation: true, nodeIntegration: false, nodeIntegrationInSubFrames: false, webSecurity: true, webviewTag: false, navigateOnDragDrop: false, spellcheck: false`. That's the exact `webPreferences` shape this ticket needs on the two windows that still say `sandbox: false` (`index.js:384-389`'s `createWindow`, `show_window.js:246-267`'s `makeWindow`) — no new security model to invent, just extend one that's already proven and tested (`dashboard/test/mockup_window.test.js:69-77`, `dashboard/test/show_web.test.js:93-97`). The preload (`dashboard/electron/preload/index.js`) already only calls `contextBridge`/`ipcRenderer` — nothing in it needs raw Node, so "move anything the preload needs Node for behind IPC" is already true; nothing to change there. "A PR body with HTML or script content: rendered inert" is already enforced and tested in `dashboard/src/components/IssueBody.jsx` + `dashboard/test/issue_body.test.jsx:44-46` (react-markdown without `rehype-raw`, plus an explicit script/`onerror`/`iframe` strip) and in `show_window.js`'s own sandboxed `<iframe sandbox="allow-scripts">` framing (`csp.test.js:84`) — this ticket's job is to keep those passing under the new major, not rebuild them.

**Simplest sufficient approach:** Electron's `ipcMain.handle` already turns a handler that throws (e.g. destructuring `{ repo, number }` out of `undefined`) into a rejected promise at the renderer — most of the 143 handlers in `index.js` get "unexpected arguments → rejected" for free from that existing shape. The real gap is the smaller set of handlers whose argument flows straight into `fs`/`child_process`/`shell.*` *without* throwing on a wrong type (e.g. a non-string `path`/`slug`/`relPath` silently coerced) — those get the same guard `show.js`'s `checkShowPath`/`checkPath` already uses (allowed-roots containment + `typeof === 'string'`), not a hand-written schema per handler. That is less code than either doing nothing (fails the break-it test) or writing bespoke validation for all 146 handlers (the kind of scope-creep three prior automated attempts may have gotten bogged down in).

**Tokens:** spent on reading breaking-change notes for each Electron major skipped and on the audit of path/exec-touching handlers (one-time, necessary); saved by not re-deriving the sandboxing pattern or the HTML-inertness guarantee, and not writing a bespoke validator per handler.

**Machine:** build/sign/install/relaunch must be proven on both Macs per the acceptance criteria — that's an execution step, not a planning one; no machine preference changes anything in the diff itself.

**User impact:** removes a real, resident attack surface (GitHub-sourced PR/ticket text reaching Node through an unsandboxed preload) without changing anything Gil sees or does — pure capability gain, no behavior change for him to adapt to.
