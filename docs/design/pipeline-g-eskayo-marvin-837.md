## North-star fit

**Reuses before adding anything new:**
- `lib/job_catalog.py`'s `machine` field + `lib/job_units.py`'s `_skip_reason`/`install()` (already-built portable-job placement, marvin#911) — AC1 is a one-line catalog edit, no new installer logic.
- `lib/health_checks.py`'s `_MACHINE_STATE_SCRIPT`/`_run_machine_state` and `check_recent_errors` — already pure local-measurement code; the fix drops their existing SSH fan-out loop rather than inventing a new read path.
- `dashboard/electron/main/triggers.js`'s `createTriggerHub().watchFiles()` (already wired for `docs`, `agents`, `quarantine`, `support`, `goals` — CONTEXT.md "Triggers over polling") — AC3's "the view updates when the sweep writes" is one more `watchFiles()` registration, not a new mechanism.
- `index.js`'s existing `refreshCatalog()` in-flight-promise de-dup (lines ~755-763) — the same shape fixes "two refreshes at once: one sweep."
- `dashboard/electron/main/stamped.js` + `peer_copy.js` (marvin#1223) — already give a "producer's copy, labelled with its age, never silently red" for a stale/unreachable Mac; already tested (`peer_copy.test.js`: "the producer asleep or Tailscale down: our own copy, stale, with its age and Mac"). Nothing new needed for that break-it bullet.

**Simplest sufficient approach, and where it spends vs. saves:** AC1 is a single dict-value change. AC2 is a deletion of SSH round-trips, not an addition — the two check functions that fan out over SSH today (`check_machine_state_everywhere`, `check_recent_errors`) measure facts that are already 100% local (dashboard build time, webhook uptime, GitHub token, disk, memory, launchd jobs, this Mac's own errors — see `_MACHINE_STATE_SCRIPT`, lines 1195-1233, which touches nothing but `$HOME`). Once AC1 lands, the peer computes these about itself every 15 minutes anyway, so re-measuring it over SSH from the other Mac is pure waste (an extra SSH round-trip + a full remote Python/bash invocation, every 15 minutes, for data the peer already has). Dropping it moves these two checks from the 200 s `CROSS_MACHINE_BUDGET_S` tier to the 60 s local `CHECK_BUDGET_S` tier — strictly less time and network per sweep, and it's the direct fix for "so the Macs disagree" (two independent SSH measurements of the same peer, racing against that peer's own 15-minute sweep, is exactly how two numbers for "the same fact" diverge). AC3 is also a deletion (an `await` that blocks the IPC reply) plus one more file-watch registration already used five times elsewhere.

**Scope boundary (resolved by an existing decision, not guessed):** `health_checks.py` has several *other* SSH call-sites (ollama model availability, pipeline circuit-breaker, sync-log stuck detection, repo/mirror sync, merge-service reachability). These are left untouched. CONTEXT.md's "Shared truth" entry (line 601-604) already draws this line: *"Each Mac owns its own load, tokens, sessions and failures"* — exactly the machine-state and recent-errors data — while PRs/tickets/claims are GitHub-owned, merges are Mini-owned, and sync/breaker/model-registry are their own separate mechanisms with their own ownership story. The ticket's "what Gil sees" paragraph only diagnoses the machine-state/errors fan-out (job placement + "Macs disagree" on the composite view); it doesn't ask to re-litigate the other mechanisms. No Decisions section needed — this is grounded in a recorded decision, not an open question.

**Leaves the user more capable, not more passive:** a Mac's Health tab now tells the truth about *that* Mac from its own measurement, on its own schedule, instead of occasionally showing a 6-hour-old snapshot or a number the other Mac silently disagrees with. "Refresh now" stops holding the UI hostage for up to 99 s.

**Where it runs:** no change — `health-check` stays a `both`-placed launchd job (laptop + Mini), per ADR 0032/0033 and `job_units.py`'s existing per-Mac install path.

## Tests first

*(bullets map 1:1 to the issue's "How we'll try to break it" list; the rest are the required misuse sweep)*

1. **Peer asleep → its last copy, with age, not red.** Already covered by `dashboard/test/peer_copy.test.js` ("the producer asleep or Tailscale down: our own copy, stale, with its age and Mac") — run as a regression check, not rewritten. Add one `lib/tests/test_health_checks.py` case: a *local* `health-check` sweep that hasn't run in a while still returns its last-written, stamped data with age — never fabricates "red" for staleness (staleness is the stamp's job, not a check's).
2. **Two refreshes at once → one sweep.** New `dashboard/test/health.test.js`: calling `requestHealthSweep(execFileAsync)` twice before the first's `execFileAsync` resolves invokes the underlying spawn exactly once; both callers' promises settle together.
3. **A sweep that takes 3 minutes.** Same test file: with `execFileAsync` mocked to resolve after an artificial delay (or never, within the test), `health:refresh`'s IPC handler (exercised via `requestHealthSweep` + `readHealthStatus`) returns well under 1 s — i.e., the handler never `await`s the sweep itself. Also: once that slow run finally resolves (or throws), the in-flight guard clears so the *next* refresh starts a fresh sweep (it doesn't get stuck "already running" forever).
4. **AC1 enforcement, not just the catalog value.** New `lib/tests/test_job_units.py` case: `job_units.install(["health-check"], os_name="macos", role="laptop", ...)` installs (doesn't skip/remove) now that `job_catalog.JOBS["health-check"]["machine"] == "both"`; same for `role="mini"`. (Today's `_skip_reason` would say "placed on the mini only" and actively *uninstall* it from the laptop — the literal bug in the issue.)
5. **No check measures another Mac over SSH (machine-state).** Rewrite `test_check_machine_state_everywhere_covers_every_device_and_marks_asleep`: assert the local-only check never shells out to `ssh`/a remote target (inject the local-script runner only; no `remote_devices()`/`remote_macs()` call); assert its `*_ts`/`gh_token`/disk/memory severities for *this* Mac still classify red/yellow/green exactly as before (`evaluate_machine_state` itself is unchanged and keeps its existing ~15 tests).
6. **No check measures another Mac over SSH (recent errors).** Rewrite the six `check_recent_errors` cross-machine tests (`red_when_one_keeps_repeating_on_either_mac`, `amber_for_a_one_off_today`, `an_unreachable_mac_is_unknown_not_clean`, `an_asleep_mac_is_asleep`, `a_remote_read_that_fails_is_unknown_not_clean`, `groups_from_both_macs_are_newest_first`) into local-only equivalents: red for a repeating error on *this* machine, amber for a one-off, no `remote`/`reachability` parameter left to inject a fake peer — because there's no peer read left to fake.
7. **Each dependency failing.** The local measurement script (`_run_machine_state`) raising/non-zero-exiting, or the local error source raising, still yields a result (`_unknown`/yellow), never crashes `run_all()` — covered by `guarded()`'s existing behavior; add a direct case if the simplified function bypasses it.
8. **Bad/empty/huge/malformed input.** `health-status.json` read mid-write (truncated/invalid JSON) by `stamped.read`/`readStamped` already returns `missing: true`, never throws — regression-test, not new.
9. **Wrong permissions.** `~/.claude/logs` unwritable on the laptop after this change still fails the same way `write_status()` already fails today (`OSError` surfaces, not swallowed) — regression-test only; this ticket doesn't touch `write_status`.
10. **A person's mistake.** Gil manually removes `~/Library/LaunchAgents/com.marvin.health-check.plist` on the laptop (or it was never installed because of the old "mini only" placement) — the next `job_units.py install` call re-installs it there, per test 4.
11. **Repeats/concurrency beyond the UI.** Noted, not newly tested: the launchd-scheduled sweep and a manual "Refresh now" could in principle overlap as two separate OS processes (the in-memory de-dup in `health.js` only covers two IPC calls within the same Electron process). `write_status()` already writes whole-or-not-at-all, so the worst case is duplicate work, never a corrupt file — accepted as out of scope for this foundation ticket rather than adding a cross-process lock.
