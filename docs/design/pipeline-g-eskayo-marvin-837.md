## North-star fit

**Reuses:** `lib/machine_resources.py` (`sample_now`/`append_sample`/`read_samples`, header comment "No SSH... Cross-machine visibility via existing ~/.claude sync layer: dashboard reads both machines' files off local disk") is the exact pattern this ticket needs for health: one `.<device_id>.` file per machine, written by a local-only sampler, visible to other machines purely because `~/.claude` already syncs. `lib/job_units.py`'s `machine`/`mac_placement`/`install()` already auto-places `config/jobs/<name>.json` per `job_catalog.JOBS[name]["machine"]` — `health-check` already has a portable job definition (`config/jobs/health-check.json`) and is *already* installed unconditionally on the Linux box; only the job-catalog placement value is wrong. `dashboard/electron/main/stamped.js` (`readStamped`/`fromData`) and `dashboard/electron/main/device_identity.js` (`resolveDeviceId`/`peerHosts`) already give "which Mac, how old" for a file and "who are my peers" with zero new code. `dashboard/electron/main/triggers.js` (`createTriggerHub`) is the existing file-watch→IPC-push mechanism (used for `docs`, `activity`, `support`, `agents`, `goals`) — health has no topic yet. `dashboard/electron/main/metrics.js`'s `{subsystem}.{machine}.json` directory-scan/merge is the precedent for merging N per-device files into one timeline/index. CONTEXT.md's existing "Shared truth" decision ("Each Mac owns its own load, tokens, sessions and failures. Whether a Mac is alive is owned by the others") already states the target architecture; this ticket is the implementation of a decision already on record, not a new one.

**Simplest sufficient approach:** no new sync channel, no HTTP peer-copy fetch, no new daemon. Every SSH-based cross-machine check in `lib/health_checks.py` has a local-only half already (it measures itself, then loops over peers via SSH to measure them too) — delete the SSH loop, keep the local half, give the output file a per-device name so two Macs syncing `~/.claude` don't clobber each other's copy (same reason `machine-resources.<device_id>.jsonl` isn't `machine-resources.jsonl`). The merge of N machines' files back into one Vitals view happens in the Electron main process, which already does exactly this kind of merge for `metrics.js` and already has the per-check-id "@<device>" / " — <device>" label convention baked into `HealthDashboard.jsx`'s flat `checks.map(...)` — so the merge step can synthesize those same suffixes and the renderer needs no changes.

**Where it spends/saves:** removes ~8 SSH round-trips per sweep (each with its own multi-second timeout), which is the direct cause of the 64–99 s sweep time the ticket complains about — so the "no ssh" fix and the "refresh is fast" fix are the same fix, not two. Electron-side, "Refresh now" moves from a blocking 60 s `execFileAsync` await to a fire-and-forget kick-off + file-watch push, which is less idle-wait CPU in the renderer, not more work.

**Phone-OS direction:** more OS-shaped — "ask any machine, get the true answer about itself, trust the others' self-reports" is exactly the decentralized, no-single-point-of-truth shape north star 2 wants, and removes a hard dependency on the Mini being up to know anything about the laptop.

**More capable, not more passive:** this is pure infra; Gil doesn't do anything manually either way, except the one real human step this ticket can't avoid — physically running the installer on the laptop once (see Task 10).

## Scope note (resolved from the ticket text, not a Decision)

`lib/mirror_health.py`'s `check_mirror_sync_everywhere` (a Mac SSHing into `mac-mini-2012` to read its mirror state) is **out of scope**. The ticket's own wording is Mac-scoped throughout ("every registered **Mac**", "No check measures another **Mac** over ssh"), consistent with ADR 0069's hard Mac/non-Mac distinction used everywhere else in this file. The box is also pull-only — it has no push channel back to the Macs' synced `~/.claude`, so it structurally *can't* self-report the way a Mac can; fixing that for real is the "push in plan P2" the ticket explicitly defers. Leaving this one check alone is therefore the correct reading, not a shortcut.

## Tests written first

Adversarial cases per the ticket's "How we'll try to break it" plus the standard misuse sweep. Existing `lib/tests/test_health_checks.py` already has extensive coverage of the functions being changed (`test_check_repo_sync_everywhere_covers_local_and_reachable_remote`, `test_check_machine_state_everywhere_covers_every_device_and_marks_asleep`, `test_pipeline_breaker_remote_query_handles_unreachable_machines`, `test_check_sync_stuck_*`, `test_query_ollama_models_remote_returns_none_on_ssh_failure`, `test_check_model_availability_unknown_when_remote_machine_unreachable`, `test_an_unreachable_mac_is_unknown_not_clean`, `test_an_asleep_mac_is_asleep`, `test_check_machine_reachability_reports_asleep_for_a_closed_laptop`) — these get rewritten to assert the local-only behavior, not deleted outright, since the laptop/asleep/unreachable *semantics* move to the new JS merge layer and need equivalent coverage there instead.

1. **job_catalog placement** — `job_catalog.JOBS["health-check"]["machine"] == "both"`; `health_checks.JOB_PLACEMENT["health-check"] == "both"`; `job_units.install(["health-check"], os_name="macos", role="laptop")` no longer skips it (today it does — this is the regression test proving criterion 1).
2. **No SSH left in the sweep** — a static/behavioral test that `subprocess.run`/`subprocess.Popen` is never called with `"ssh"` as an argument anywhere `health_checks.default_checks()` reaches, for every check in the list (mock `subprocess.run` to raise if `cmd[0] == "ssh"` or `"ssh" in cmd`, run `run_all()`, assert it never fires). This is the single highest-value regression test for criterion 2 and should fail loudly if any future check regresses.
3. Per-converted-check, local-only behavior:
   - `check_sync_stuck()` with no `host`/`remote` param: only this Mac's own `sync-log.md` entries feed in; a remote Mac's stuck entries never appear (replaces the remote-unreachable/asleep cases).
   - `check_pipeline_breaker()`: only local `failure_breaker.tripped()` + local staleness; a trip recorded under another device id is absent.
   - `check_repo_sync()` (renamed from `_everywhere`): one result per `SYNCED_REPOS` entry, local only; no `@<device>` suffix.
   - `check_machine_state()` (renamed): one result set, local only, via `_run_machine_state(None, script)`.
   - `check_recent_errors()`: returns only this machine's error groups; no `reachability` param needed.
   - `check_model_availability()`: per the Decision — either drops the remote branch and reports local presence only, or (if "rebuild at merge" is chosen) still drops the remote branch here and the fleet view moves to a new JS-side test.
   - `check_stale_relay()`: calls `stale_relay.everywhere(macs=[])` — asserted via a spy that `macs` passed is always `[]`.
4. **Machine reachability moves out of the Python sweep**: `run_all()`/`default_checks()` no longer produce a `"machine"` check id at all; `check_machine_reachability` and its ssh "echo ok" probe are deleted from the sweep (kept or removed from the module per implementation — covered by test 2's blanket ssh assertion either way).
5. **Per-device status file**: `write_status()` writes to `health-status.<registry_id()>.json` for every machine kind (replacing the old `health-status.json` / `health-status.local.json` pull-only special case); two different `registry_id()` values produce two different paths with no collision — test with `monkeypatch` on `machine_profile.registry_id`.
6. **Dedup concurrent sweeps**: two overlapping invocations of whatever launches the sweep (the scheduled launchd tick racing a manual "Refresh now") result in exactly one sweep running; the second is a no-op, not a crash or a half-written file. Also: a sweep that takes 3 minutes doesn't block a "Refresh now" click from returning — it returns immediately, marks "already running," and the eventual write still fires the file trigger.
7. **Refresh now (`health.js`/`index.js`)**: `health:refresh` resolves in well under 1 s regardless of how long the underlying sweep takes (mock `execFileAsync` to hang; assert the IPC promise still resolves fast); calling it twice back-to-back only invokes `execFileAsync` once (in-flight dedup).
8. **File-trigger wiring**: writing a new `health-status.*.json` file into the watched logs dir fires a `'health'`-topic trigger exactly once per debounce window (reuse `dashboard/test/triggers.test.js`'s harness style); the renderer's listener re-fetches `health:status` on that topic.
9. **Peer-copy merge (new function, e.g. `readAllMachinesHealth`)**:
   - Bad/empty/huge/malformed input: a peer's file is missing → shown as "no report yet", never crashes, never shown as current.
   - A peer's file is garbage JSON / not an object → treated like `stamped.js`'s existing `missing: true` path, not a crash.
   - A peer's file is stale beyond its `tolerance_s` → shown with its age, severity never escalated past yellow purely from staleness (ticket: "Peer asleep: its last copy shows with its age, not red").
   - Every registered device, including one that has never run the new job (`health-check` only just placed on the laptop) → "no report yet" instead of silently omitted.
   - Two machines' `checks` arrays merge into one flat list with synthetic device suffixes, no id collisions even when both machines happen to produce the same local check id (e.g. both report `"token"`).
   - `overall`/`coverage` of the merged result is the worst/union across machines, not just the local machine's.
10. **Repeats/concurrency/wrong order**: reading the merge while a peer's file is mid-write (temp-file-and-rename, per `write_status`'s existing atomic-write contract) never observes a half-written file — rely on `write_status`'s existing temp+rename guarantee and add a test that a `.tmp` file in the dir is never picked up by the merge's directory scan.
11. **A person's mistake**: `job_units.py install health-check` run with `role=None` (registry doesn't know which Mac this is) still raises `JobError` naming "which Mac" (existing behavior — regression-guard it still applies once placement is "both").
