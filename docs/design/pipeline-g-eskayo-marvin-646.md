## North-star fit

**Reuses:** `lib/instance.py` (`engine_repo()`, `owner()`, `tickets_repo()`, `feature_enabled()`) and its JS twin `dashboard/electron/main/instance.js` — both already built and tested (PR before #646, ADR 0071 step 1-2). This ticket is pure call-site migration onto that existing primitive, plus closing the one gap the first outside install's audit found in the primitive itself (silent `UPSTREAM` fallback). It also reuses `dashboard/electron/main/profiles.js` / `metrics.js`'s existing pattern of `import { instancePath } from './instance.js'` for main-process modules, and `lib/tests/test_instance.py`'s ratchet regex/grandfathered-list mechanism (PR #633) as the pass/fail gate — no new test infrastructure needed, just making the list shrink.

**Simplest sufficient approach:** no new abstractions. Every one of the ~84 files gets the same move — read the owner/repo from the one place that already knows it, instead of a local literal. The two genuinely new pieces are kept minimal: (a) a `NotConfigured` exception so "no origin, no config" fails loudly instead of defaulting to `G-Eskayo/marvin` (closes the audit's gap), and (b) one small renderer-side helper (`dashboard/src/lib/instance.js`, IPC-backed) because six `.jsx` files run in the Electron renderer and can't `import fs`/`child_process` the way `instance.js` does — that's a new file, but it's one general primitive serving 6 call sites, not per-component special-casing, so it fits the composability principle rather than violating it.

**Token/compute cost:** this is almost entirely mechanical substitution across many small files — cheap per file, expensive only in count. No runtime cost change: `instance.py`/`instance.js` are already O(1) per process after the first call (lru_cache / module-level cache), so swapping a literal for a function call doesn't add measurable overhead. The plist templating piece is the one genuinely new (small) capability.

**Phone-OS / capability test:** this is pure reliability and shareability work — a second person's MARVIN currently leaks tickets, comments and reads into Gil's public repo, which is a "breaks silently" failure the north stars explicitly forbid (north star 2). Fixing it doesn't change what Gil can do, but it's a precondition for anyone else running MARVIN at all, which the "best tool for making tools" north star (4) cares about directly. No automation is being added that takes a human's own judgment away — it's not a capability/passivity trade-off at all.

## Tests I will write first

Mapped to the ticket's four acceptance criteria plus the extra one from the comment, plus the breakage checklist (bad/empty/huge/malformed input, dependency failure, repeats/concurrency, wrong permissions, stale state, person's mistakes):

1. **Ratchet goes to zero** (`lib/tests/test_instance.py::test_no_new_engine_file_hard_codes_an_owner_account_or_machine`, `test_the_grandfathered_list_only_shrinks`): no code change needed — these two tests already exist and already enforce "no new file, and the list only shrinks." I will empty `instance_grandfathered.txt` as the very last implementation step; its red→green over the course of the work *is* the ratchet, so no new test is needed here — but I will add one line to the existing list-only-shrinks test's own self-check to confirm `GRANDFATHERED == set()` once done, so a future revert is caught immediately rather than silently passing because the list-only-shrinks check only fires when something is *removed*, not when something new creeps back in after the list is already empty (that's the *other* existing test, `test_no_new_engine_file_hard_codes_...` — confirming both are in play together, not duplicating).
2. **Fail loudly with no origin + empty instance.json** (new): `instance.engine_repo()`, `.owner()`, `.tickets_repo()` each raise `instance.NotConfigured` when there is no git `origin`, no `instance.json`, and no config keys — replacing (not just extending) today's `test_no_origin_falls_back_to_the_config_then_the_upstream`'s `assert instance.engine_repo() == instance.UPSTREAM` branch, which currently encodes the exact bug reported. Mirror in `dashboard/test/instance.test.js`.
3. **UPSTREAM still reachable when it's genuinely the origin**: a repo whose real `origin` *is* `G-Eskayo/marvin` still resolves normally (the fail-loud path must not break Gil's own machines) — parametrize over the existing `at()`/`_engine()` fixture.
4. **No `G-Eskayo` in any request with a fake instance** (`acme/marvin`): a test that monkeypatches `instance` (or points `MARVIN_INSTANCE_DIR`/`MARVIN_ENGINE_DIR` at a temp repo with `origin=https://github.com/acme/marvin.git`) and then calls the real functions in `ticket_pipeline.py`, `mr_raiser.py`, `project_onboard.py`, `purpose_metrics.py`, `decisions_submit.js`, `activity.js`, `mr_repos.js`, `ProposalsSection.jsx` (via its data path) with a fake `gh`/`exec`, asserting no call string, URL or rendered text contains `"G-Eskayo"`. Real collaborator rule per the north stars: use the actual `instance.py`/`instance.js`, not a mock of them — only `gh`/`exec`/filesystem get faked.
5. **Writers error rather than write to the wrong repo**: for each of the 5 named writers, a test with `NotConfigured` raised from `instance` asserts the writer raises/propagates rather than catching and defaulting.
6. **Dashboard "not set up" state**: a test (wherever the fail-loud is surfaced — boot data or a dedicated IPC handler, per Decision A) that an unconfigured instance produces a `{configured: false}`-shaped result the renderer can show, not a thrown error that crashes the window.
7. **Plist templates carry no literal `/Users/gileskayo`**: extend `lib/tests/test_no_hardcoded_home.py`'s `git grep` glob to include `*.plist`, and add a test for the new substitution function (`{{HOME}}` → real `$HOME` at install time; a plist that doesn't contain the placeholder is left untouched; a missing `$HOME` env fails loudly rather than writing a broken plist).
8. **Breakage checklist, applied to the ratchet/instance work specifically:**
   - *Bad/empty/malformed:* `instance.json` is `{}`, `[]`, a non-dict, truncated/corrupt JSON, `{"owner": 7}` — already covered by existing parametrized tests; extend the same parametrization to also assert `NotConfigured` is raised (not a blank-instance read) specifically for the *no-origin-and-empty-config* combination, while a corrupt-but-origin-present config still falls back to blank-instance behavior as today (origin is still derivable).
   - *Huge input:* a `REPOS`/`tracked_repos`-shaped instance.json with hundreds of entries (relevant to `morning_brief.py`, Decision C) doesn't blow up `_config()`'s O(1)-after-first-call cache.
   - *Each dependency failing:* `git remote get-url origin` exits non-zero, times out, or `git` itself is missing (`FileNotFoundError`) — existing `_origin_repo()` already catches `OSError, SubprocessError`; add the case where `instance_dir()` exists but its parent is unreadable (permission error) and assert it still reads as blank, not a crash.
   - *Repeats/concurrency:* two processes reading/writing `instance.json` while the pipeline is mid-run (ticket_pipeline.py's existing `fcntl.flock` pattern is unrelated and untouched, but `instance.reset()` racing a concurrent `_config()` read across threads — confirm `lru_cache` is safe here, since Python's GIL makes this a non-issue for the current single-process model; document rather than over-test).

   - *Stale state:* an `instance.json` left over from a different, previously-configured clone (e.g. machine reimaged, repo re-cloned fresh with no origin yet set) must not resolve to the stale `engine_repo` silently — this is exactly what `test_the_real_origin_beats_a_stale_engine_repo_in_the_config` already checks for engine_repo(); it does not yet check `tickets_repo()`/`owner()`, which I'll add.
   - *A person's mistakes:* owner hand-edits `instance.json` and leaves `"engine_repo": ""` (empty string, not missing key) — `_str()` already returns `None` for blank strings, confirm `NotConfigured` still fires rather than an empty-string repo reaching `gh`.
9. **Plist and evidence-script category tests** (F, I from the table): `health_checks.py`'s legacy-prefix check still matches `com.gileskayo.` for Gil's own machine today (regression guard) while also matching a hypothetical `com.acme.` for a fake instance; evidence scripts' fixture data contains no real project name after the fix (grep-based test, same shape as #1).

## Decisions

<!-- marvin:decisions -->
### fail_loud_shape: How should `engine_repo()`/`owner()`/`tickets_repo()` fail when nothing can be derived?
- [ ] A: Raise a new `instance.NotConfigured` (Python) / throw `Error` (JS) from each getter; every caller either lets it propagate (writers) or catches it once, at the dashboard's boot layer, to show a "not set up" screen
- [ ] B: Getters return `None` instead of raising; every call site must explicitly check for `None` before using the value (more call sites to get right, no exception-safety net)

### not_set_up_surface: Where does the dashboard show "instance not set up"?
- [ ] A: A blocking boot-time screen (alongside the existing #431 boot sequence), before any tab loads
- [ ] B: Inline per-tab banners wherever `engineRepo()`/`owner()` is actually called (MR Review, Activity, Docs, Boards) — tabs that don't need it still work

### git_author_identity: Where does `mr_raiser.py`'s commit author (`AUTHOR = "Gil Eskayo <...>"`) come from for a non-Gil instance?
- [ ] A: New `instance.json` fields (`author_name`, `author_email`), required before the pipeline can commit on that instance
- [ ] B: Read from `git config user.name` / `user.email` in the worktree at commit time (no instance.json change, relies on git already being configured)

### map_publish_target: `brain-map/publish_map.py`'s hardcoded snapshot-publish repo
- [ ] A: New `instance.json` field (e.g. `map_publish_repo`); publish_map.py no-ops with a clear log line when unset, since the public brain-map snapshot is itself an opt-in add-on
- [ ] B: Leave brain-map's public-snapshot deploy as a Gil-only script not meant to run on another instance at all (document it as such, exclude from the ratchet via the add-on exemption rather than wiring it through instance.json)

### historical_literals: `migrate_ticket_stages.py` (`OLD_OWNER="G-Eskayo"`) and `ticket_stages.py` (`KNOWN_OWNERS={"g-eskayo":"G-Eskayo"}`) correctly describe *old data*, not the live owner — the AC says the grandfathered list goes to zero, which conflicts with leaving these as literals
- [ ] A: Add a narrow, file-scoped ratchet exemption (e.g. a `# marvin:identity-literal` marker line the regex/test respects) for lines that parse historical data, so they stay literal and still come off the grandfathered list
- [ ] B: Keep these two files permanently on the grandfathered list (document why in a comment next to the list) rather than building a new exemption mechanism for two lines

### tracked_project_list: `morning_brief.py`'s `REPOS = ("G-Eskayo/marvin", "G-Eskayo/clarity-captions", "G-Eskayo/marvin-mobile")` — Gil's personal cross-project brief list
- [ ] A: New `instance.json` field (e.g. `tracked_repos`), defaulting to `[engine_repo()]` only, so a fresh instance's brief doesn't silently try (and fail) against Gil's other private repos
- [ ] B: Reuse `lib/project_catalog.py`'s existing catalog (already lists known projects per repo) instead of adding a new instance.json field — `morning_brief.py` calls into the catalog rather than owning its own list

### pr_batching: 84 files + the instance fail-loud fix + plist templating is large for one PR
- [ ] A: One PR, organized as separate commits per category (A–J above), so review can go commit-by-commit
- [ ] B: Split into sequential PRs by subsystem (instance.py/js fail-loud + its tests first; then lib/*.py; then dashboard/electron+webhook-server; then dashboard/src/components + the new renderer helper; then brain-map/skills + plists), each shrinking the grandfathered list incrementally so the ratchet test is green after every PR, not just the last one

### evidence_home_guard: `dashboard/scripts/*_evidence.mjs`'s `HOME === '/Users/gileskayo'` safety check (meant to stop these scripts from ever running against a real home) is itself a hardcoded-owner literal, and several of these files already also check `!HOME.includes('sandbox')` alongside it
- [ ] A: Drop the `HOME === '/Users/gileskayo'` check entirely where a `sandbox`-substring check already exists next to it (redundant, and only ever true for one specific person anyway)
- [ ] B: Replace it with a positive check instead of a negative one — require `HOME` to end in a `*-sandbox` suffix (or similar convention) rather than checking it *isn't* one specific real path
