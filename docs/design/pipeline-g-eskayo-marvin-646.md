**Reuses:** `lib/instance.py` / `dashboard/electron/main/instance.js` (ADR 0071, PR #633/#635) as the single derivation point — `engine_repo()`, `owner()`, `tickets_repo()`, `feature_enabled()` — already built, tested (26 Python + 18 JS tests), and used by nobody yet. **Simplest sufficient approach:** this ticket is a mechanical substitution (replace a literal with a function call) across ~84+ files, not a redesign. The only two places needing real new code are (a) a small `is_configured()`/`require_configured()` pair (Python + JS) so "writers" fail loudly instead of silently defaulting to `UPSTREAM`, and (b) one new `instance:get` IPC channel for the handful of renderer `.jsx` files that currently hardcode a GitHub URL/comparison. Everything else is swapping `"G-Eskayo/marvin"` for `instance.tickets_repo()` (or `owner()`/`engineRepo()` where that's what's actually meant).

**Where it spends tokens:** this is a wide, shallow ticket (many files, low complexity per file) — appropriately executed as one batched pass per subsystem rather than 84 individual review cycles, and it buys nothing to over-design; a human reviewer gains nothing from 84 near-identical diffs explained individually.
