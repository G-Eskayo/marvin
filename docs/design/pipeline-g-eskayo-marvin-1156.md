## North-star fit

**Reuses:** `lib/model_registry.py`'s `register()`/`touch_last_used()` (lines 142–177) — the `fcntl.flock` pattern this repo already uses to serialize writers to a shared, machine-wide file — and `lib/tests/test_model_cache.py::test_two_worktrees_at_once_fetch_once` (threading-based concurrency test against a real `fcntl` lock) for the test style. `lib/model_cache.py` itself (the "#1114 — fetch a gitignored model once per machine" tool) was the first thing I checked, but its `ensure()` explicitly refuses any `--into` target outside the calling worktree (`"{t} is outside the worktree {cwd}"`), and chromadb's ONNX cache lives at a fixed, worktree-independent `~/.cache/chroma/...` — so its CLI doesn't fit, only its locking *idea* does.

**Root cause, verified against the real collaborator's source** (`~/.agents/venv/.../chromadb/utils/embedding_functions/onnx_mini_lm_l6_v2.py`, chromadb==1.5.9 per `requirements-ci.txt`): `_download_model_if_not_exists()` does an unlocked check-then-act on a *shared* path — `os.path.exists(tar.gz)` → `_verify_sha256()` (opens the file) → maybe re-`_download()` (which `os.remove()`s the file on a hash mismatch) → `tarfile.open()`. Under `-n auto` (pytest-xdist, wired by `lib/affected_tests.py:parallel_args`), every worker is a separate OS process, and `conftest.py:make_test_home` links each worker's `TEST_HOME/.cache` to the *same* real `~/.cache` — so on a cold CI runner, several workers call the default embedding function for the first time at once and race on that one file. One worker's `_verify_sha256` `open()` at `onnx_mini_lm_l6_v2.py:24` loses a TOCTOU race to another worker's `os.remove()`, producing exactly the observed `FileNotFoundError: ... onnx.tar.gz`. This is CI-infra flakiness, not content introduced by the merge main-red pinned (`cc830481`, an unrelated portfolio-status change) — reverting that merge would fix nothing, so I'm fixing forward with a small change, not reverting.

**Why this shape is the simplest sufficient fix:** serialize the *existing* lazy download with a lock keyed on its own cache folder, rather than (a) eagerly pre-warming before workers spawn, which would force a network attempt on every test invocation even ones that never touch chromadb — a resource regression and a hazard in network-restricted sandboxes — or (b) mocking the embedding function everywhere, which would silently change what `test_argument_mapper.py`/`test_continuity_checker.py`/`test_cross_machine_merge.py` actually exercise. The lock only ever fires when some test already needed the real default embedding function, exactly as today; the only new unconditional cost is importing `chromadb.utils.embedding_functions.onnx_mini_lm_l6_v2` once per test process (confirmed no network call at import time — checked `chromadb/__init__.py` for telemetry/socket calls, there are none), bounded and non-network, same order of cost conftest.py already pays elsewhere (e.g. its unconditional `project_catalog` subprocess call).

**Tokens/resources:** spends a few lines of new code and one new small, independently-testable module instead of touching any of the 14+ production call sites that use chromadb's default embedding function; saves CI minutes and future debugging time by closing a nondeterministic failure that would otherwise keep flaking main red.

**User capability:** this is pure infra hardening — it makes CI outcomes trustworthy again (green means green), which is a precondition for everyone trusting the merge gate; it doesn't change any behavior a person interacts with.

No Decisions needed — this is a fully-determined, mechanical infra fix with no owner-facing design choice.

## Tests (write first)

New file `lib/tests/test_chroma_onnx_lock.py`, testing `lib/chroma_onnx_lock.py` against a **stub class** shaped exactly like `ONNXMiniLM_L6_V2` (a `DOWNLOAD_PATH` class attribute + a `_download_model_if_not_exists` method) so the tests are fast, offline, and don't need real chromadb/network — plus one integration check against the *real* class to prove the wiring took effect.

1. **The exact original race, reproduced against the real shape** — a stub `_download_model_if_not_exists` that does the real control flow (check exists → sleep at the TOCTOU gap → open-to-verify) while a second thread deletes the file mid-gap: unprotected, this reliably raises `FileNotFoundError`; wrapped with `protect()`, it doesn't. This is the test that would have caught marvin#1156.
2. **Serializes concurrent callers** — two threads (mirroring `test_two_worktrees_at_once_fetch_once`'s style) call the wrapped method at once on the same stub; assert peak concurrency inside the original is 1.
3. **Still calls through to the original** — asserts the original's side effect (a call counter / marker write) actually happens; the fix must not just skip or swallow the work.
4. **Propagates the original's exception** — the wrapped original raises (simulated "no network" dependency failure); the wrapper must re-raise, not hide it.
5. **Lock is released after an exception** (stale-state / repeats) — after a failing call, a second call must still acquire the lock promptly, not hang on a stuck lock left by the first.
6. **Idempotent double-wrap** — calling `protect()` twice on the same class must not nest the lock (which would self-deadlock within one call); the second call is a no-op.
7. **Missing private method (dependency drift)** — a stub lacking `_download_model_if_not_exists` (future chromadb rename): `protect()` must not raise; conftest import must survive a chromadb upgrade that changes this shape.
8. **Creates the lock's parent directory if missing** — fresh machine, `DOWNLOAD_PATH.parent` doesn't exist yet; must `mkdir`, not `FileNotFoundError`.
9. **Lock file not creatable (wrong permissions)** — parent dir read-only: must propagate the `PermissionError` (fail closed) rather than silently proceeding unlocked.
10. **Integration check** — import the real `chromadb.utils.embedding_functions.onnx_mini_lm_l6_v2.ONNXMiniLM_L6_V2` and assert `conftest.py`'s module-level wiring already patched it (a marker attribute), proving the fix is actually live for every test process, not just unit-tested in isolation.

Verify fails if any of 1–10 is removed, weakened (e.g. widening a timing window instead of asserting serialization) or skipped without the corresponding conftest.py code changing too.
