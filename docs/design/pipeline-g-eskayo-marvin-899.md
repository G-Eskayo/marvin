## North-star fit

**Reuses:** the whole age/staleness mechanism already exists and is wired end-to-end — `lib/stamped.py` (`stamp`/`from_data`/`read`, marvin#1223) and its JS twin `dashboard/electron/main/stamped.js` (`fromData`/`readStamped`) already compute `ageS`, `stale`, `toleranceS` for `health-status.json`. `lib/health_checks.py:write_status` already stamps with `STATUS_TOLERANCE_S = 20*60`, and `dashboard/electron/main/health.js:readHealthStatusFresh` (the `health:status` IPC handler) already returns `status.copy = {ageS, stale, toleranceS, host, legacy}` to the renderer. `dashboard/electron/main/boot_data.js` already computes a test-injectable `ageMin` and a `fresh` boolean and already renders a distinct "stale" wording path (`HEALTH STALE`) with amber (`unknown` tone → `var(--amber)` in `boot.css`). None of that backend/data-layer work is missing — issue #899 is a **pure dashboard-display gap**: two of the three named surfaces (the Health/Vitals tab's `OverallBadge` verdict line in `dashboard/src/components/HealthDashboard.jsx`, and the header tab dot in `dashboard/src/App.jsx:140`) never look at `status.copy` at all today — they colour only by `overall`, so a frozen-but-"green" sweep stays green forever. The third surface, the boot verdict (`dashboard/electron/main/boot_data.js:verdictOf`), already goes amber when stale but never shows the age when things are fine, and its stale wording doesn't match the ticket's own phrasing or expose a distinct `tone`.

**Simplest sufficient approach:** add one new pure, DOM-free module `dashboard/src/lib/health_view.js` (same shape as the existing `dashboard/src/lib/boot_view.js`, which is pure functions tested via `dashboard/test/boot_view.test.js` without mounting anything) exporting a single `verdictLine(overall, copy)` function that both `OverallBadge` and the `App.jsx` tab dot call — one source of truth for "can this verdict be trusted right now," instead of two independent judgments. For the boot verdict, extend the existing `verdictOf` in `boot_data.js` with an `ageWords()` helper and a new `tone: 'stale'` (which falls through `boot_view.js:bannerTone`'s existing default to `'unknown'`/amber styling — no CSS or `boot_view.js` change needed). No backend (Python) changes at all.

**Where it spends/saves:** zero new Claude-call cost (pure display logic, no new data sources); reuses the already-running 15-minute `com.marvin.health-check` sweep and its existing `Refresh now` button (`health:refresh` IPC) as "the fix" the ticket asks for — building a second, differently-labelled button would duplicate #837's job for no benefit.

**More capable, not more passive:** yes — today a frozen sweep can report "All checks healthy" forever with no visible age, which is exactly the silent-failure the north stars rule out ("nothing broken silently"). This makes a stuck sweep visible and actionable within its allowed gap, on all three surfaces named in the ticket, without the owner having to notice a stopped clock by hand.

Reading the two prior failed attempts: both automated comments gave no diagnostic detail (one was a queue timeout, the other "regressed" after 3 iterations with no specifics), and no branch/PR diff from either attempt exists in this worktree's history to inspect. My best-supported hypothesis, from reading `dashboard/test/boot_data.test.js`, is that `d.verdict` is checked with exact-string equality in several places (e.g. `toEqual({ nominal: true, tone: 'nominal', text: 'ALL SYSTEMS NOMINAL' })`) — a change that makes the verdict always carry its age necessarily changes that exact string, and a prior attempt that didn't update every one of those pinned assertions would show as a regression. I account for that below by updating every affected assertion explicitly.

## Tests first

From "How we'll try to break it":
1. **Freeze the sweep job: "healthy" must not survive.** `health_view.test.js`: `verdictLine('green', { ageS: 10_000, stale: true, toleranceS: 1200 })` must NOT say "all checks healthy" — it must say the verdict is old and the sweep hasn't run, with amber severity, even though the last real reading was green. Same for `overall: 'red'` — staleness overrides the severity-specific wording, not just green. Mirror in `boot_data.test.js`: a `GREEN()` fixture aged past `STALE_MINUTES` must yield `tone: 'stale'`, `nominal: false`, text containing `OLD` and `SWEEP HASN'T RUN`.
2. **Change the system clock forward and back.** `boot_data.test.js`: call `buildBootData` with `now` moved forward past `STALE_MINUTES` (verdict flips to stale) then with `now` moved back under the tolerance from the same `generated_at` (verdict returns to nominal with age text) — proves nothing is cached/sticky, each call re-derives purely from `(now, generated_at)`. `health_view.test.js`: boundary test, `ageS === toleranceS` is not stale, `ageS === toleranceS + 1` is (matches `lib/stamped.py`'s documented "exactly at tolerance is not stale").
3. **The sweep runs but writes a partial snapshot.** `boot_data.test.js`: extend the existing "corrupt or wrongly-shaped health file" case with one that has `checks: []`/missing `generated_at` — must stay non-nominal, never crash. `health_view.test.js`: `verdictLine(overall, undefined)` and `verdictLine(overall, { ageS: null })` — both must report "age unknown", not crash, not claim healthy.

Misuse the section didn't call out:
4. **Bad/malformed input.** `health_view.test.js`: `overall` is `undefined`, `null`, `123`, `'purple'` → must normalize to the warning colour/wording, never silently render "healthy" (mirrors the existing convention in `dashboard/electron/main/boot_data.js:17`, `level = (s) => LEVELS.has(s) ? s : 'yellow'`). `ageS` is negative, `NaN`, or `Infinity` → must not crash and must not print `NaN min ago`.
5. **Huge input.** `ageS` of several weeks (e.g. `20_000_000`) → renders as "days ago" / "X days old", not a garbled number.
6. **A person's mistake / repeat action.** Clicking the existing `Refresh now` button while a stale verdict is showing clears the amber once the fresh sweep writes — already covered by `handleRefresh`'s existing `refreshing` guard; add one `health_view.test.js`/render-level case asserting that `verdictLine` re-evaluated against a fresh `copy` (new `ageS: 0, stale: false`) stops showing the stale wording — i.e. nothing in the new code remembers "it was stale a moment ago."
7. **Wrong/stale producer state.** `copy.producerUnreachable`/`copy.from` (peer-copy fields already returned by `readHealthStatusFresh`) must not confuse `verdictLine` — it only reads `ageS`/`stale`/`toleranceS`, so pass a `copy` object carrying those extra fields and assert they're ignored, not throw.

- Line 58–65 (`is NOT nominal when … older than the stale limit`): assert `tone: 'stale'` and the new wording, not just "not NOMINAL."
- No change needed to the "issues" (`N CRITICAL`/`N WARNING`) or "HEALTH UNKNOWN" (missing/corrupt file) branches — those are untouched by this ticket.
