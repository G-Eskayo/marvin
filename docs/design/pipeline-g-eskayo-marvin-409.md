## North-star fit

Reuses, not adds: the same `_gh`/`gh=` injection seam, `fcntl.flock` + atomic tmp-then-`os.replace` idioms, `project_catalog.slug()`, and the `STATE_PATH` convention already written into `lib/seal_beta_tickets.py` in this worktree — this attempt is a **repair pass on existing, mostly-correct code**, not a rewrite. `lib/seal_beta_ingest.py`, `config/launchd/com.marvin.seal-beta-ingest.plist`, and `CONTEXT.md` are already correctly wired (main()'s `check_and_file=None` seam, the plist comment, the CONTEXT.md section with the stale-doc correction note) — none of those need further changes beyond what's below. The simplest sufficient approach is six targeted, line-scoped fixes plus the tests that would have caught each, not a redesign: every defect the review found is a missing edge-case guard in otherwise-sound logic (sort key, None-handling, merge-vs-replace, dict validation, fail-closed count), not a wrong shape.

Token/spend: stays near zero on quiet runs (no breach ⇒ zero `gh` calls, confirmed by existing `breaches()` tests). The fixes add no new gh calls; fix 5's per-breach try/except and fix 3's state-merge are pure Python, free at runtime.

Checking the prior doc's stated fit against current code: its claims hold — `_gh`'s absolute-path resolution to `~/.agents/bin/gh` (the [GitHub gate](reference-github-gate.md)) is already in place; the only gap the prior round's *notes* (not must-fix) raised was that `_gh` doesn't call `project_catalog.run_env()`, so anything the gate binary itself shells out to still inherits launchd's bare PATH. That's real but not in this round's must-fix list — I've scoped it as an optional, cheap addition in the task list, not a blocker.

Leaves the user more capable: once these six defects are closed, Gil can trust `seal-beta-ingest`'s nightly run not to silently corrupt its own ticket-dedup state or crash on one malformed device report — exactly the "verified, not assumed" bar for anything that touches a public repo unattended.

## Fixes for the must-fix findings (each with its catching test)

1. **`lib/seal_beta_ingest.py` `_stats()` sort crash (around line 255/274).** `sorted(rated_tuples)` and `sorted({... os ...})` compare tuples/values that can mix `None` and `str` (one report missing `build`, or a non-string `os`). Fix: `sorted(rated_tuples, key=lambda t: tuple(str(x) for x in t))` and `sorted({str(r.get("os")) for r in recs if r.get("os")})`-style coercion before sorting. *Test:* a `report()` fixture where one conversation's `app.build` is `None` (or device `os` is non-string) alongside a normal rated conversation on another `device_model` → `_stats()`/`summarize()` completes without `TypeError`, and `rated_reports`/`os_versions` still contain both entries as strings.

2. **`lib/tests/test_seal_beta_ingest.py:438` real-gh test.** `test_main_lazy_imports_check_and_file_when_not_injected` calls `sbi.main(...)` with no injection, so on an unlucky future fixture it would hit the real `seal_beta_tickets.check_and_file` → real `_gh` → real `~/.agents/bin/gh` against the public `clarity-captions` repo. Fix: `monkeypatch.setattr(seal_beta_tickets, "check_and_file", fake)` (import `seal_beta_tickets` directly, not via `sys.modules` membership) before calling `main()`, and assert the **patched callable** was invoked with the right `store_dir` — never assert `"seal_beta_tickets" in sys.modules` (true from other tests regardless). *Test:* the rewritten test itself is the catching test — it fails loudly (`fake` never called, or a real subprocess spawned) if the lazy-import path regresses to bypass the injected seam.

3. **`lib/seal_beta_tickets.py` state replace-vs-merge (~line 435-441).** `confirmed_state` (only keys touched successfully *this run*) is written as the entire new `tickets.json`, dropping every key for a device that isn't breaching this run or hit a transient `gh` failure. Fix: load `state` (validated as a dict, see fix 5) at the top, and at the end write `{**state, **confirmed_state}` — previously known keys survive unless explicitly updated. *Test:* seed `tickets.json` with a key for a device that doesn't appear in this run's `summary.json` breaches; after `check_and_file()`, that key is still present in the written state unchanged.

4. **`lib/seal_beta_tickets.py` `issue_body` `None` crash (~line 408).** `issue_data.get("body", "")` returns `None` (not the default) when the API sends `"body": null`, so `.strip()` raises `AttributeError`; a non-dict `issue_data` fails the same way on `.get`. Fix: `issue_body = (issue_data.get("body") if isinstance(issue_data, dict) else None) or ""`. *Test:* `gh` fake returns `'{"state": "OPEN", "body": null}'` for the view call → no crash, falls through to the edit path (empty stored body never equals the rendered body, so it edits) and the run still completes with a confirmed state entry.

5. **`lib/seal_beta_tickets.py` non-dict state + unwrapped per-breach errors (~line 340ff).** A `tickets.json` that parses to a list/string makes `key in state` raise `TypeError`; and `render()`/the create-or-edit sequence has no per-breach try/except, so one bad entry aborts the whole loop *and* loses the final state write for every breach already processed. Fix: after `json.loads`, `state = state if isinstance(state, dict) else {}`; wrap each iteration's body (`render()` through create/view/reopen/edit) in `try/except Exception as e: result["breaches"].append({"problem": breach.get("problem"), "status": "error", "key": ..., "detail": str(e)}); continue`. *Test:* (a) `tickets.json` containing `["not", "a", "dict"]` → `check_and_file()` treats it as empty state, no crash; (b) a `summary.json` with one `by_device` entry whose `model_ids` is itself a dict (so `render()`'s `",".join(...)` raises `TypeError`) alongside one normal breaching entry → the normal breach still gets filed (confirmed in the final state), and the malformed one shows `status: "error"`, never an uncaught exception.

6. **`lib/seal_beta_tickets.py` `rated_reports` fallback overcounts (~line 135-140).** When `rated_reports` is missing/not a list, the code falls back to `entry.get("rated", 0)` — the per-conversation count, which overcounts because two conversations from one report (one phone call) still only represent one tester data point. Design fix #8 says fail closed instead. Fix: `rated_reports = entry.get("rated_reports"); num_rated_reports = len(rated_reports) if isinstance(rated_reports, list) else 0` — delete the `rated` fallback branch entirely. *Test:* a `by-build`-scoped build entry (or any entry) with `rated: 2` but `rated_reports` entirely absent → `breaches()` does **not** yield a `low_rating` breach (previously it would have, incorrectly, via the fallback).

### reopen: A matching ticket already exists but Gil closed it, and the same (device, problem) breach appears again on a later run. What should happen?
- [ ] A: Reopen and update the existing ticket — treat it as a regression of the same problem (current code's default)
- [ ] B: Leave the closed ticket alone and file a new ticket, with the old ticket's number mentioned in the body

### scope: Thresholds are computed per device model today. Judge them against the device's all-time aggregate, or only its most recent build?
- [ ] A: All-time aggregate — simplest; a problem fixed in a later build can keep the ticket open forever since old bad data never ages out (current code's default, `SCOPE = "by-device"`)
- [ ] B: Most recent build only — reflects current app state and lets a ticket naturally stop re-triggering once a build fixes it
