**Simplest sufficient approach:** each must-fix is the smallest change that removes the actual defect — e.g. moving one `_safe_text()` call inside `_slug()` so both call sites compute the marker from the same canonicalization, rather than inventing a second identity mechanism. ## Root causes and fixes (each maps 1:1 to a must-fix finding)

1. **`stuck` check crashes on non-numeric** (`seal_beta_tickets.py:120`-ish): `endings.get("stuck") and endings["stuck"] > 0` raises `TypeError` for `"lots"`, caught by `run()`'s blanket `except`, failing the *entire* run for one bad device. Fix: use the existing `_num()` helper, same as `lag`/`rating` already do: `stuck = _num(endings.get("stuck")); if stuck is not None and stuck > 0:`. Apply the same guard to the per-build `stuck_count` copy (currently copies `build_endings["stuck"]` raw, which can render an arbitrary string into a public ticket).

2. **Marker computed from two different strings** (`render_body` vs `find_existing`): `render_body` reassigns its local `device` to `_safe_text(raw, max_len=100)` *before* calling `marker()`; `find_existing` calls `marker()` on the untouched raw device. `_slug`'s own regex (`[^a-z0-9]+` → `-`) does *not* produce the same result as `_safe_text`'s transforms for inputs with `<!--`/`-->` or length > 100, so the two sides diverge and the exact-marker filter silently never matches → new duplicate ticket every run. Fix: move canonicalization **inside** `_slug()` itself (`safe = _safe_text(device, max_len=100)` then the existing regex on `safe`), and change every caller (`render_body`, `find_existing`, the sort key in `file_or_update_breaches`) to pass the **raw** device string into `_slug`/`marker`/`ticket_key`. One canonicalization point, same input everywhere — this is the fix the review explicitly asked for, not a second parallel one.

3. **Cursor advances by the full window even on an early break** (`file_or_update_breaches`): `cursor_next` is computed as `(start_idx + window_size) % len(...)` unconditionally, so breaches skipped by a gate deferral get rotated past and starved — the exact bug the cursor was built to fix. Fix: track `advanced` (count of breaches that actually got a disposition — created, updated, unchanged, or hard-failed) and only set it on the deferral break-point's `offset`, not `window_size`. `cursor_next = (start_idx + advanced) % len(sorted_breaches)`. A hard (non-deferred) `GhError` still advances `advanced` (that breach will reappear fresh next run since breaches are recomputed from `summary.json`, not accumulated — not starving it); only a `deferred` break withholds advancement so the same breach is retried at the very next run.

4. **`--dry-run` mutates real state**: currently the loop still runs for every breach in the window even when `dry_run`, incrementing `tickets_deferred` and `cursor_next`, and `run()` persists that to `ticket-status.json` — overwriting the last real run's status and advancing the real rotation. Fix: `file_or_update_breaches` returns an early, pure preview (`tickets_would_process: window_size`, `cursor_next: cursor` **unchanged**) with **zero** gh calls when `dry_run=True` — it never enters the per-breach loop at all, so it can't conflate with the real `tickets_deferred` meaning (a genuine gate refusal). `run()` never calls `_write_json(status_path, ...)` when `dry_run=True` — nothing on disk changes, full stop.

5. **Test (`test_gh_gate_refusal_stops_processing_at_first_deferred_error`) uses one breach, proves nothing**: with one breach, the existing `break` (which is already present and correct in the current code) and "no break" are indistinguishable. Fix: rewrite with **two** breaches and a fake that refuses every call; assert the fake's `list` action was called **exactly once** (not twice) and `tickets_deferred == 1` (not 2) — this fails if the `break` is ever removed, passes only because it's there.

6. **The harness itself can't test what it claims to**: `fake_gh_ok` still does `monkeypatch.setattr(subprocess, "run", fake_run)` with exact-dict matching, returns at most one candidate, and ignores `--state`/`env`. Fix: replace it with a real executable `gh` (a short `#!/usr/bin/env python3` script written to `tmp_path/bin`, `chmod 0o755`, first on `PATH`) backed by an `fcntl`-locked JSON state file holding `issues` (number/title/body/state) and a `calls` log (argv + an env-marker it was handed). It implements `issue list` (loose multi-token substring match over title+body, honors `--state`), `create`, `edit`, `reopen`, and an injectable `force_rc` to simulate a gate refusal. Tests read the same JSON file back to assert on calls/state instead of a captured closure — mirrors `test_gh_gate.py`'s `_fake_gh` idiom, extended to be stateful.

**Notes folded in (cheap, same files, same must-fix areas):**
- `gh issue list` has no `--limit`; with many devices the exact match can fall outside the default 30. Add `--limit 100`.
- `issue.get("body", "")` returns `None` when GitHub sends `"body": null`, and `marker_text in None` raises uncaught `TypeError`. Use `issue.get("body") or ""`.
- The early-return (missing/corrupt/non-dict summary) and exception paths in `run()` write a status with no `cursor_next`, silently resetting rotation to 0 on a transient blip. Fix: every write path carries forward the `cursor` value that was just read. Also guard the read itself: `cursor = prev.get("cursor_next", 0); cursor = cursor if isinstance(cursor, int) else 0` (a corrupted non-int value must not make `cursor % len` raise).
- `_safe_text` does a single-pass replace, which the review notes can leave a residual `<!--`/`-->` from adjacent fragments; fix by looping the two replacements to a fixed point (bounded — each pass strictly shrinks the string whenever it still matches, so it terminates). Also strip/replace literal backtick characters in the device name — the body already wraps the device in `` `...` ``, and an un-stripped backtick in the device name breaks out of that code span, re-enabling `@mention` parsing. `s = s.replace("`", "'")` alongside the existing control-char and comment-marker neutralization.
- The "unchanged" skip compares bodies byte-for-byte; GitHub may normalize line endings/trailing whitespace, which would make every run re-edit with no real change. Compare after `.strip()` + normalizing `\r\n`→`\n` on both sides.
- The module's own docstring (line 16, `seal_beta_tickets.py`) still says `ticket-status.json` is used "for tracking and idempotency" — stale relative to `CONTEXT.md`'s already-correct wording (lines 1269–1275, already fixed in this worktree). Match it: hidden markers are the sole idempotency mechanism; the cursor is a rotation hint only.
- **Testability root cause for "confirm `env_builder=project_catalog.run_env` has no side effects":** Python binds default-argument values once at function-definition time. `env_builder=project_catalog.run_env` is bound at import, so `monkeypatch.setattr(project_catalog, "run_env", stub)` **cannot** affect it — any test that doesn't explicitly pass `env_builder` is silently invoking the real `project_catalog.run_env()`, which reads the real `~/.claude/.gh-token` and inserts the real `~/.agents/bin` gate dir from this actual machine's filesystem into `PATH`. Fix: change the three gh-calling functions' signature to `env_builder: Callable | None = None` and resolve inside the body: `env = (env_builder or project_catalog.run_env)()`. This makes late-binding real, so a test-module-level autouse fixture that monkeypatches `project_catalog.run_env` to a harmless stub is a genuine, reliable backstop — not just cosmetic — for any test that forgets to pass `env_builder` explicitly.

### recurrence: A filed ticket is closed and the same (device, problem) breach recurs later. What should the bot do?
- [ ] A: Reopen the existing ticket and update its body automatically (current code's default — no human in the loop)
- [ ] B: Leave it closed and do nothing (closing is treated as "won't fix"; the breach never resurfaces unless Gil reopens it himself)
