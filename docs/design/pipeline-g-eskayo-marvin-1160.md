## North-star fit

- **Reuses before adding anything new:**
  - `lib/project_onboard.py:31-38` (`TRIAGE_LABELS` / `TRIAGE_LABEL_COLORS`) — the only place today that already names "every project's core label set" with colours. The new catalog becomes the one source of truth; `project_onboard.py` will import from it instead of keeping its own copy, so the "core subset" can't drift between onboarding and the gate.
  - `lib/pr_ticket_check.py:repo_here()` — the existing no-API-call "repo from cwd" resolver (`git remote get-url origin`), and its `_URL`/`_PR_URL` issue/PR-URL regexes — reused for resolving which repo a healed `gh label create` targets, instead of inventing a second resolver or spending a `gh repo view` call.
  - `lib/pr_images.py`'s argv-parsing shape (`_VALUE_FLAGS`-style flag walk used by `parse_pr_call`) and `bin/gh`'s existing `try: import X … except ImportError: pass` fail-open wiring for `decisions_check` / `pr_ticket_check` — the new `label_catalog` module plugs into `main()` the same way, so "module missing or broken → gate still works" comes for free from the established pattern rather than new code.
  - `config/project_tags.json` (`projects` keys) is the existing, already-live registry of known project ids — reused as the validation set for the `project:<id>` family instead of hardcoding a list that will go stale.
  - `~/.claude/marvin-network.json` devices (read the same direct-JSON way `bin/gh:_pull_only_here` already does) — reused for the `claimed:<machine>` family instead of importing `machine_profile` (keeps the gate's "stdlib only, starts fast" property intact).
  - `lib/tests/test_gh_gate.py`'s `_fake_gh`/`_run_gate` harness — reused and extended (a smarter fake `gh` that understands `label create` and simulates "not found") rather than a new test-execution scaffold.
- **Simplest sufficient approach:** heal happens once, at the choke point (`bin/gh`'s existing non-terminal subprocess path), as a bounded retry loop over the *same* call with one label fixed per iteration. No new daemon, no new storage format — the catalog is a plain Python dict module, and the only new log fields are additions to the row `bin/gh` already writes to `gh-calls.jsonl`.
- **Where it spends/saves tokens:** spends nothing at runtime (pure Python, no model calls); saves agent/person time industry-wide by turning a hard crash that hides a real failure (the portfolio #19 incident) into either a silent, correct heal or a clear, correctly-scoped refusal.
- **Phone-OS direction:** indirectly — it's reliability plumbing (north star 3: "approved work never stops for a reason unrelated to the work"), not itself OS-shaped.
- **More capable or more passive:** more capable — the owner stops being the de facto "create the label by hand" step; MARVIN now makes that judgment call itself, with the boundary case (an uncatalogued name) still correctly escalated rather than silently invented.
- **Ticket's own stated fit** ("North star: 3, human experience") checks out against the code: confirmed, no correction needed.

## Tests first (one per "How we'll try to break it" item, using the triage-narrowed list since that's the actual scope)

All as `lib/tests/test_label_catalog.py` (pure-function unit tests) plus end-to-end additions to `lib/tests/test_gh_gate.py` (real subprocess against a fake `gh`, extending `_fake_gh`/`_run_gate`):

1. Several missing labels in one call: a fake `gh` that 404s on `a`, then `b`, then succeeds — all catalogued → both get created, in turn, within a bounded number of retries (assert retry count ≤ a small fixed bound, not unbounded).
2. Flag-shape coverage: `--add-label a,b` (comma split), `--label=a` (`=`-form), `-l a` (short flag + separate value), repeated `--add-label x --add-label y` → all parsed into the same add-set. Add and remove combined in one call (`--add-label a --remove-label b`) where `b` is missing → `b` is dropped from `--remove-label` and the call retried with `a` untouched.
3. A typo (`ready-for-agnet`, `project:marvn`) → never created; original error preserved; hint names the catalog module.
4. `'x' not found` where `x` was passed as `--assignee`/`--milestone`/`--repo` (not a label in this call) → untouched, even when `x` happens to be a catalogued label name — guarded by checking the matched name against the call's own parsed add/remove label lists, not just "does this string exist in the catalog".
5. Repo resolution: `--repo o/r`, `-R o/r`, an `issue`/`pr` edit target that's a full GitHub URL, `GH_REPO` env, and bare cwd (via `pr_ticket_check.repo_here`) each resolve correctly; an issue-URL target must never create the label against the cwd repo even when `-R`/`GH_REPO` are absent.
6. Two writers creating at once: `gh label create` returning "already exists" counts as a successful heal, not a failure that aborts the retry.
7. An existing label in different case (`Bug`) or with a person's own colour: the heal path only runs `label create`, never `label edit` — it can't ever touch an existing label's colour.
8. `gh label create` fails for a real reason (archived repo, no permission, simulated rate-limit stderr) → original error stands, exactly one create attempt, no loop; gate's own rate-limit classifier (`classify_refusal`) still sees the real refusal text (fed the right stderr, not a healed one).
9. `--body-file -`: a fake gh that requires stdin content to echo it back, called through a healable `pr create --body-file -` where the label also needs healing → stdin bytes are read once by the gate and replayed identically on the retry.
10. stdout/exit code parity: a call that heals ends with the *same* stdout and exit code as a call where the label already existed (no partial/duplicate stdout from the failed first attempt); the first attempt's error text is never printed to the user once healing succeeds.
11. Read-only commands (`issue list --label x`) and `gh api ...` are never intercepted by the heal path (not in `{issue,pr} × {create,edit}`).
12. Catalog module missing/broken (`ImportError`, or a `label_catalog.py` that raises on import) → `bin/gh` still runs the original call once and returns its result unchanged, same as the existing `decisions_check`/`pr_ticket_check` fail-open tests.
13. Misuse not explicitly listed but required by the north stars' adversarial-test principle: a huge/malformed label name in the stderr match (control characters, multi-KB string) doesn't blow up the regex or get written unsanitized into the log; a name containing `/`, spaces, or shell metacharacters is still only ever passed to `subprocess.run([..., name, ...])` (argv list, never a shell string) so it can't be used for injection.
14. Logging/probe: a healed call and a refused (uncatalogued) call each produce exactly one `gh-calls.jsonl` row (not one per retry) carrying enough structure for `purpose_metrics._label_problems` to count both; the new `label-problems` probe reads that log over the 7-day window and sums correctly (unit test against a synthetic log, mirroring `test_purpose_metrics.py`'s existing probe tests).
15. `project_onboard.py`'s `TRIAGE_LABELS`/`TRIAGE_LABEL_COLORS` after the refactor are byte-identical in value to before (regression guard that the dedup didn't change the core set), and its existing `_apply_labels` tests still pass unmodified.

Only the *final* attempt's stdout/stderr/rc reach the user; a terminal, uncatalogued-name hint is appended to the kept original error.
