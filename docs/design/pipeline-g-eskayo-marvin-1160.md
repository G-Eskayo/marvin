## North-star fit

**Reuses, not reinvents:**
- `lib/project_onboard.py:31-38` (`TRIAGE_LABELS`/`TRIAGE_LABEL_COLORS`) — the only existing single source for the 5 triage labels' colours; `lib/label_catalog.py` becomes their new home and `project_onboard.py` imports from it instead of keeping its own copy (no behavior change, removes one duplicate source the ticket exists to prevent).
- `lib/main_red.py:134-135` (`_ensure_label`) — already-live colour/description conventions for `main-red` (`b60205`) and `project:<id>` (`c5def5`, `"Work on {id}"`); reused verbatim rather than inventing new ones.
- `lib/ticket_pipeline.py:400` — already-live colour/description for `needs-reengagement` (`d93f0b`, "Sent back: rebuild on the current base branch"); reused instead of deny.js's uncoloured fallback.
- `lib/decisions_check.py` / `lib/pr_ticket_check.py` — the `flag, eq, value = arg.partition("=")` argv-parsing idiom, and `pr_ticket_check._URL`/`_PR_URL`/`repo_here()` for resolving which repo a call targets (URL, `--repo`/`-R`, `GH_REPO`, cwd). `pr_ticket_check.py` already reaches into `decisions_check`'s private helpers, so a second module reusing `pr_ticket_check`'s is established practice here, not a new pattern.
- `bin/gh`'s own existing shape — `ui_evidence_refusal`/`pull_only_refusal`/`_gh_json` already live directly in `bin/gh` for concerns too tied to its subprocess/stdin plumbing to factor out; the retry/heal orchestration follows the same placement, while the new `lib/label_catalog.py` stays pure data + lookup (no subprocess calls), matching how `pr_images.py` stays pure while `bin/gh` does the asking.
- `lib/purpose_metrics.py`'s `PROBES` dict + the `_mirror_failures`/`_slot_wait_timeouts` shape (read one local JSONL, filter by time window, return a float) — `label-problems` is one more entry in that same table, not a new metrics mechanism.

**Why this is the simplest sufficient approach:** the healing decision ("is x actually a label this call passed, and is it catalogued") is answered entirely from argv + a static/local-file lookup — no network call is needed to decide whether to heal, only to execute the heal (`gh label create`) and the retry. Catalog membership for the dynamic `project:` family is deliberately scoped to `{"marvin"} ∪ config/project_tags.json` keys for this slice (not the full per-machine `project_catalog.py`, which needs GitHub calls and is per-machine/unsynced) — broader coverage is explicitly the follow-up `label_catalog.py check|sync` ticket's job, not this one's. `claimed:<machine>` is treated as an unvalidated wildcard family: its suffix comes from `machine_profile._label()` (code), never human-typed, and no attack in this ticket's "how we'll try to break it" list probes a bad `claimed:*` value — inventing a static machine registry just to validate it would add coupling for no tested benefit.

**Tokens:** spent once, in `bin/gh`'s hot path, on a cheap regex match against already-parsed argv before any network call; saved repeatedly by preventing a crashed send-back (the original incident) from burning a full diagnose-and-redispatch cycle, and by deleting the now-redundant need for every caller (`ticket_claim.py`, `box_build.py`, `deny.js`) to carry its own ad hoc "create on first use" fallback — this slice doesn't remove those (out of scope), but stops new ones from ever needing to be written.

**North star 3 (human experience):** a send-back that currently dies on an unrelated `'needs-reengagement' not found` and silently drops out of the queue will instead heal and surface the real reason (or its real refusal) — the owner stops losing visibility into genuine problems to a plumbing bug.

## Design

**`lib/label_catalog.py`** (new, stdlib-only, no subprocess calls):
- `FIXED: dict[str, dict]` — name → `{"color", "description"}` for: the 5 triage labels (sourced values, see below), `bug` (`d73a4a`), `enhancement` (`a2eeef`), `breaking-change` (`5319e7`, ADR 0028), `needs-reengagement` (`d93f0b`, reused from `ticket_pipeline.py`), `main-red` (`b60205`, reused from `main_red.py`), `linux-ok` (`c2e0c6`), `from-box` (`0e8a16`, reused from `box_build.py`), `purpose-metric` (`bfd4f2`), `missed-purpose` (`e99695`), `watch` (`fbca04`), `regression` (`d73a4a`), `hold` (`bfdadc`), `priority:p0`..`p3` (red→green gradient).
- `CORE: frozenset[str]` — the 5 triage labels + `bug`, `enhancement`, `needs-reengagement`, `priority:p0..p3` (documented judgement call; consumed by nothing yet, just metadata for the follow-up onboarding ticket).
- `known_project_ids() -> set[str]` — `{"marvin"} | json.load(config/project_tags.json)["projects"].keys()`, fails to `{"marvin"}` on any read error.
- `lookup(name) -> dict | None` — `FIXED[name]`, else `{"color": "c5def5", "description": f"Work on {id}"}` for `project:<id>` when `id in known_project_ids()`, else `{"color": "ededed", "description": f"Claimed by {m}"}` for any `claimed:<m>`, else `None`.
- `label_call(argv) -> dict | None` — `{"cmd", "add": [...], "remove": [...]}` for `issue|pr create|edit`, parsing `--add-label`/`--label`/`-l` (add) and `--remove-label` (remove), handling `=`, repeats, and comma-separated values; `None` for anything else.
- `failed_label(stderr, call) -> tuple[str, bool] | None` — regex `'([^']+)' not found`; returns `(x, is_add)` only if `x` is literally one of `call["add"]`/`call["remove"]` — this is what keeps an assignee/milestone/repo "not found" untouched even when it happens to equal a catalogued name.
- `call_repo(argv, env, here=pr_ticket_check.repo_here) -> str | None` — `--repo`/`-R` value, else an issue/PR URL among the positional args (reusing `pr_ticket_check._URL`/`_PR_URL`), else `env.get("GH_REPO")`, else `here()`.
- `without_label(argv, label) -> list[str]` — argv with `label` dropped from every `--remove-label` value; a flag left with nothing survives gets removed; used for the "already absent" removal case.

**`bin/gh`**: a new `_heal_labels(real, argv, env, say, log)` used only inside the existing non-interactive branch, only when `label_catalog.label_call(argv)` is not `None`. It loops (cap `MAX_LABEL_HEALS = 10`): run `[real, *cur_argv]` capturing **both** stdout and stderr (a change from today's stderr-only capture, scoped to this call path only — every other call keeps its current stdout-inherited behaviour untouched); on success or a non-label failure, stop. On a label failure: if it was a `--remove-label` value, drop it from `cur_argv` via `without_label` and retry (no `gh` call needed — "the outcome already holds"); if it was `--add-label`/`--label`/`-l`, look it up — catalogued: `gh label create <name> --repo <call_repo> --color … --description …` (an "already exists" failure from that create counts as success, matches case-insensitively per gh's own rule), then retry the *same* `cur_argv`; uncatalogued: stop, keep the original failing output, and `say()` a hint naming `lib/label_catalog.py`. Every heal and refusal is a separate line appended to `gh-calls.jsonl` (`{"t", "caller", "cmd", "label_healed": name}` / `{"t", "caller", "cmd", "label_refused": name}`), independent of the call's normal completion line. `--body-file -` is detected before the first attempt; when present, stdin is read fully once into memory and fed to every attempt via `Popen(..., stdin=PIPE).communicate(input=...)` instead of being inherited. The whole thing is behind `try: import label_catalog except ImportError: label_catalog = None`, and `_heal_labels` is skipped entirely when `label_catalog is None` — a broken/missing catalog module falls back to exactly today's behaviour. This only touches `issue|pr create|edit`; a person at an interactive terminal (today's `subprocess.call` branch, no stderr capture) is left completely alone — healing never applies there, since the ticket's authoritative (triage-generated) attack list doesn't test it and the existing terminal path already has no stderr to inspect.

**`lib/project_onboard.py`**: `TRIAGE_LABELS`/`TRIAGE_LABEL_COLORS` become thin re-exports of `label_catalog` data (same values, so `test_project_onboard.py` needs no change) instead of a second copy.

**`lib/purpose_metrics.py`**: new `_label_problems(path=None, days=PROBE_WINDOW_DAYS, now=None) -> float`, same shape as `_mirror_failures`/`_slot_wait_timeouts` — reads `~/.claude/logs/gh-calls.jsonl` (via `github_usage.read_jsonl`, matching `_github_calls`), counts rows in the window with `"label_healed"` or `"label_refused"`. Registered in `PROBES["label-problems"]` with a threshold (baseline 1, per the ticket's Recurrence check) and a description citing this ticket.

**Out of scope (explicitly, per the ticket's "Left for follow-up"):** `deny.js`'s `err.message`/`err.stderr` bug stays as-is; `ticket_claim.py`'s and `box_build.py`'s own "create on first use" fallbacks stay (now just redundant-but-harmless once `bin/gh` heals first, since `gh` on `PATH` resolves to the gate); no onboarding change; no `label_catalog.py check|sync`; no literal-scanning test.

## Tests (written first)

Against the generated "How we'll try to break it" list, in `lib/tests/test_label_catalog.py` (pure functions) and additions to `lib/tests/test_gh_gate.py` (end-to-end, reusing its `_fake_gh`/`_run_gate` fixtures with a new fake that fails `N` times then succeeds, recording every argv it was called with) and `lib/tests/test_purpose_metrics.py`:

1. Several missing labels in one call (`--add-label a,b` where both are missing): each created in turn, bounded retries, one real `gh` call per heal — not more than `MAX_LABEL_HEALS`.
2. `--add-label a,b`, `--label=a`, `-l a`, and repeated `--add-label` flags all parse into the same add-set.
3. Add and remove in one call, with the removed label missing: the add half heals/retries normally, the missing remove half is just dropped from argv, nothing is created for it.
4. A typo (`ready-for-agnet`, `project:marvn`) is never created; the original "not found" error and rc are preserved; `say()` names `lib/label_catalog.py`.
5. `'x' not found` where `x` was passed as an assignee/milestone, not a label — even when `x` happens to equal a catalogued name — leaves the call untouched (exercises `failed_label` checking argv membership, not just error text).
6. Repo resolution: `--repo`, `-R`, an issue URL positional, `GH_REPO`, and cwd (no flag) each pick the label-create repo correctly; an issue URL for repo B with cwd in repo A never creates the label in A.
7. Two concurrent creators: a `label create` that fails with "already exists" (any case, e.g. `Bug`) is treated as success and the original call is retried; the existing label's colour is never touched (no `label edit` is ever called).
8. `label create` fails for a real reason (archived repo / no permission / rate limit): the heal gives up, the *original* `issue|pr` call's error and rc stand, no retry loop; and this never trips `classify_refusal`/cooldown incorrectly for a transient rate limit on the healing path itself.
9. `--body-file -`: a fake stdin is read once by the gate and the retried call receives the same bytes (verified via the fake `gh`'s recorded input).
10. `stdout`/`stderr`/rc for a call that needed no healing, and for one that healed successfully, are byte-identical to a call where the label already existed; no intermediate failed-attempt noise leaks.
11. Read-only commands (`issue list --label x`) and `gh api` are never touched by `_heal_labels` (argv doesn't match `label_call`'s healable set, so the pre-existing code path runs unchanged).
12. `label_catalog` import failing (module missing/broken) still lets `bin/gh` pass every call through exactly as today — new regression test alongside the existing `test_a_gate_started_by_the_real_gh_passes_through_unlogged`-style coverage.
13. Every heal and every refusal appends its own line to `gh-calls.jsonl`; `purpose_metrics.PROBES["label-problems"]` is registered and counts exactly those lines inside its window, ignoring older ones and ordinary call-completion lines (mirrors `test_github_calls_and_failed_headless_runs_per_day`).
14. `project_onboard.TRIAGE_LABELS`/`TRIAGE_LABEL_COLORS` still equal `label_catalog.FIXED`'s corresponding entries after the refactor (drift guard — existing `test_project_onboard.py` label tests must keep passing unchanged).
15. Misuse the ticket didn't list: an empty `--add-label=` (empty string after splitting on commas) is dropped, not treated as a label named `""`; a huge number of comma-separated labels in one flag (e.g. 50) is still bounded by `MAX_LABEL_HEALS` and doesn't hang; `label_catalog.known_project_ids()` on an unreadable/corrupt `config/project_tags.json` falls back to `{"marvin"}` rather than raising.
